# 🔧 Corrección de Parpadeo de Pantalla en Gráficas Intel i915 (FIFO Underrun / SAGV)

> [!NOTE]
> **Navegación:**
> * Anterior: [[01.1 - Sudo sin Contrasena (Passwordless Sudo)|01.1 - Sudo sin Contraseña (Passwordless Sudo)]]
> * Siguiente: [[01.3 - Creacion de Usuarios y Cuentas de Sistema|01.3 - Creación de Usuarios y Cuentas de Sistema]]
> * Volver a: [[01.0 - Core del Sistema (MOC)|📑 Índice de Capa]]

Este módulo diagnostica y resuelve de raíz los parpadeos momentáneos de pantalla negra (*flickering*) en sistemas Linux con gráficas integradas Intel (especialmente arquitecturas Skylake / HD Graphics 530) bajo compositores Wayland como **Niri** y **Hyprland**.

---

## 🩺 Diagnóstico y Causa Raíz

### Síntoma
La pantalla se oscurece durante una fracción de segundo al mover el cursor, abrir ventanas o tras un periodo breve de reposo del equipo.

### Confirmación en el Registro del Kernel
```bash
journalctl -k | grep -i "fifo underrun"
# Salida típica de error:
# i915 0000:00:02.0: [drm] *ERROR* CPU pipe A FIFO underrun
```

### Causa Técnica
En microarquitecturas Intel, la función **SAGV** (*System Agent Geyserville*) ajusta dinámicamente el voltaje y la frecuencia de la memoria RAM para economizar energía. Cada cambio dinámico introduce un pico de micro-latencia que vacía el búfer de línea de la tarjeta de video (*FIFO underrun*), ocasionando la pérdida momentánea de sincronización de la señal gráfica.

Comprobar el estado activo:
```bash
sudo cat /sys/module/i915/parameters/enable_sagv   # Y = Habilitado (causante del fallo)
modinfo -p i915 | grep sagv                         # Comprueba si el driver soporta el parámetro
```

---

## ⚠️ Caso Crítico: Initramfs y Early KMS (UKI)

En distribuciones como Arch Linux y Omarchy, el controlador `i915` se carga dentro del **initramfs** mediante el hook `kms` en `/etc/mkinitcpio.conf`.
* Por lo tanto, crear `/etc/modprobe.d/i915.conf` **no surtirá efecto en el arranque si no se regenera el initramfs**.
* Se debe regenerar la imagen unificada de kernel (UKI) mediante `mkinitcpio -P`.

---

## 🛠️ Ejecución Automatizada de la Solución

El siguiente procedimiento desactiva SAGV a nivel de kernel y regenera el initramfs:

```bash
set -euo pipefail

# 1. Crear directiva de parámetros del módulo del kernel
echo "options i915 enable_sagv=0" | sudo tee /etc/modprobe.d/i915.conf

# 2. Regenerar imágenes de arranque (Early KMS y UKI)
sudo mkinitcpio -P

echo "✅ Parámetro configurado. Es necesario reiniciar el equipo para que surta efecto."
```

> [!NOTE]
> **"No presets found" es esperado en Omarchy.** Con Limine + UKI no hay presets en `/etc/mkinitcpio.d/`, así que `mkinitcpio -P` imprime ese aviso, pero los hooks de Limine regeneran igualmente `/boot/EFI/Linux/omarchy_linux-omarchy.efi`. Para confirmar que el UKI ya contiene la directiva antes de reiniciar:
> ```bash
> t=$(mktemp -d) && cd "$t"
> sudo objcopy -O binary --only-section=.initrd /boot/EFI/Linux/omarchy_linux-omarchy.efi initrd.img
> sudo chown "$USER" initrd.img
> lsinitcpio initrd.img | grep 'modprobe.d/i915' && lsinitcpio -x initrd.img etc/modprobe.d/i915.conf && cat etc/modprobe.d/i915.conf
> cd - && rm -rf "$t"
> # Salida esperada: etc/modprobe.d/i915.conf  /  options i915 enable_sagv=0
> ```

## 🪟 Configuración Específica por Compositor

### 1. Configuración de Salida en Niri (`outputs.kdl`)

Clavis gestiona dinámicamente fragmentos en `~/.config/niri/clavis/`, por lo que la configuración del monitor debe residir en un archivo modular propio (`outputs.kdl`):

> [!IMPORTANT]
> **`outputs.kdl` es de cada máquina y no se versiona.** El `config.kdl` de [robert-flo/niri-dotfiles](https://github.com/robert-flo/niri-dotfiles) ya termina con `include optional=true "outputs.kdl";`, así que en `niri` y `sura` basta con crear el archivo (el `grep` del paso 2 detecta esa línea y no añade otra). Si falta, niri arranca con el modo preferido del monitor. Herald OS usa el mismo archivo ([[01.4 - Display Manager y Sesiones SDDM (Herald OS)|01.4]]).
> En la máquina de referencia: `HDMI-A-1`, `1920x1080@60.000`, escala 1, en `/home/niri/.config/niri/outputs.kdl`. Hay que crearlo también en `sura` si se quiere el mismo modo (ejecutando el paso 2 como `sura`).

1. **Identificar la salida y modo exacto:**
   ```bash
   niri msg outputs
   # Muestra el conector (ej. DP-1 o eDP-1), resolución y frecuencia de refresco
   ```
   > [!TIP]
   > `niri msg outputs` solo funciona dentro de una sesión de niri. Si aplicas el fix desde Omarchy/Hyprland, usa `hyprctl monitors` (los nombres de conector son los mismos; en la máquina de referencia: `HDMI-A-1`, 1920x1080@60).

2. **Crear regla fija en Niri:**
   ```bash
   OUTPUT_NAME="HDMI-A-1"  # Ajusta según tu salida detectada
   
   cat > "$HOME/.config/niri/outputs.kdl" <<EOF
output "$OUTPUT_NAME" {
    mode "1920x1080@60.000"
    scale 1
    transform "normal"
    position x=0 y=0
}
EOF

   grep -q "outputs.kdl" "$HOME/.config/niri/config.kdl" || \
     printf '\ninclude "outputs.kdl";\n' >> "$HOME/.config/niri/config.kdl"

   niri validate -c "$HOME/.config/niri/config.kdl"
   ```

3. **Si el parpadeo persiste (Desactivar plano de cursor por hardware):**
   Añade el bloque de depuración a `outputs.kdl`:
   ```kdl
   debug {
       disable-cursor-plane
   }
   ```

---

### 2. Configuración en Hyprland (si aplica)

Añadir el monitor explícito a `~/.config/hypr/monitors.lua`:
```lua
hl.monitor({ output = "HDMI-A-1", mode = "1920x1080@60", position = "0x0", scale = 1 })
```

Si el cursor ocasiona anomalías, desactivar cursores por hardware en `looknfeel.lua`:
```lua
hl.config({ cursor = { no_hardware_cursors = 1 } })
```

## 🔍 Pasos de Verificación Post-Reinicio

Tras reiniciar el sistema:

1. **Confirmar que SAGV se encuentra desactivado:**
   ```bash
   sudo cat /sys/module/i915/parameters/enable_sagv
   # Salida esperada: N
   ```

2. **Auditar el registro del kernel en la sesión actual:**
   ```bash
   journalctl -k -b | grep -i "fifo underrun"
   # Salida esperada: Vacía (sin nuevos eventos de underrun)
   ```
   Un **único** underrun justo al iniciar o cambiar de sesión en SDDM (cambio de modo de pantalla) es inofensivo. El problema que corrige esta nota son underruns **repetidos** durante el uso normal.

3. **Verificar estado de salidas en Niri:**
   ```bash
   niri msg outputs
   ```

---

## 🧯 Si el Parpadeo Persiste con SAGV Desactivado

StatIndet incluye en su configuración una directiva de depuración que espera a que la GPU termine cada frame antes de enviarlo a la pantalla:

Va en `~/.config/niri/outputs.kdl`:
```kdl
debug {
    wait-for-frame-completion-before-queueing
}
```
Después, valida con `niri validate`.

> [!WARNING]
> Niri admite **un solo bloque `debug`** en todo el árbol de configuración (`duplicate node 'debug', single node expected`). Si ya se aplicó `disable-cursor-plane`, añade la línea dentro de ese mismo bloque.

---

## ↩️ Procedimiento para Revertir

Si deseas restablecer los parámetros predeterminados:
```bash
sudo rm -f /etc/modprobe.d/i915.conf
sudo mkinitcpio -P
rm -f ~/.config/niri/outputs.kdl
```
