## 🎯 Propósito y Filosofía Zero-Guesswork

Para mantener la reproducibilidad absoluta e idempotencia en cualquier máquina nueva o reinstalación sin exponer credenciales sensibles en Git público ni requerir re-configuración manual:

1. **Cero Secretos en Texto Plano en Git:** Todas las llaves privadas (SSH `id_ed25519`, claves GnuPG, tokens OAuth de Google Drive, tokens de GitHub CLI y credenciales de servicios) se empaquetan en un único archivo fuertemente cifrado: `scripts/secrets/secrets.tar.gz.age`.
2. **Cifrado Estándar con `age`:** Utiliza `age` con derivación de clave por frase de paso (passphrase) moderna y robusta.
3. **Desbloqueo y Aprovisionamiento en One-Shot:** Con un solo comando (`./desbloquear-secretos.sh`), el administrador introduce su contraseña maestra; el script descifra en una memoria RAM temporal volátil (`/dev/shm`), distribuye los permisos y llaves en sus ubicaciones canónicas del sistema y de los usuarios, y limpia la memoria inmediatamente.

## 🔒 Procedimiento de Mantenimiento del Ciclo de Vida de Secretos

Para que cualquier agente o el administrador pueda **añadir, modificar o eliminar secretos** de forma limpia y predecible:

### Caso 1: Añadir o Modificar un Secreto (ej. Nueva API Key, nueva llave SSH o renovación de token)

1. **Exportar el paquete actual a un área de trabajo temporal:**
   ```bash
   cd /z/PJ-NIRI-rf-omarchy-workstation/scripts/secrets
   ./desbloquear-secretos.sh --export-staging /tmp/staging-secrets
   ```
   *Introduce tu contraseña maestra para extraer los contenidos a `/tmp/staging-secrets`.*

2. **Realizar los cambios deseados:**
   - Para añadir credenciales nuevas: crea la subcarpeta o archivo dentro de `/tmp/staging-secrets/` (por ejemplo, `/tmp/staging-secrets/gemini/api_key`).
   - Para actualizar una llave existente: reemplaza el archivo correspondiente (por ejemplo, `/tmp/staging-secrets/.ssh/id_ed25519` o `/tmp/staging-secrets/rclone/rclone.conf`).
   - Si el cambio requiere un nuevo destino canónico en el sistema, actualiza la sección correspondiente en `desbloquear-secretos.sh`.

3. **Re-cifrar con el asistente interactivo:**
   ```bash
   ./recifrar-interactivo.sh /tmp/staging-secrets
   ```
   *Introduce y confirma tu contraseña maestra (la pide el propio script, oculta y dos veces). El script actualizará `secrets.tar.gz.age` con permisos `0600` y te preguntará si deseas purgar `/tmp/staging-secrets` al terminar.*

   > **Contraseña: nunca se autogenera (issue #80).** Los scripts que cifran (`recifrar-interactivo.sh`, `cifrar-secretos.sh`) ya no muestran el prompt de `age -p` (que ofrece generar una frase aleatoria si se deja vacía). Leen la frase ellos mismos: vacía o no coincidente → se vuelve a pedir. Antes de cifrar comprueban que la frase **abre el paquete actual**; si no, la rechazan y la vuelven a pedir (sin terminal abortan con código 3 sin tocar el paquete), así un typo no puede dejar el bundle con una clave desconocida. Para **rotar** la contraseña a propósito: `RECIFRAR_NUEVA_CLAVE=1 ./recifrar-interactivo.sh /tmp/staging-secrets` (pide la actual y luego la nueva dos veces). La frase se pasa a age por un pipe (`age-plugin-batchpass` con `AGE_PASSPHRASE_FD`, incluido en age ≥ 1.3) o, si el plugin no existe, por una pseudo-terminal; nunca se escribe a disco. Lógica común en `scripts/secrets/lib-frase.sh`.

   > **Reemplazo seguro (ambos scripts, `cifrar_paquete_seguro` en `lib-frase.sh`):** `cifrar-secretos.sh` aplica la misma salvaguarda de pérdida de entradas que `recifrar-interactivo.sh`. El nuevo ciphertext se escribe junto al destino (`.secrets.tar.gz.age.tmp.XXXXXX`, ignorado por git), se descifra y su lista se compara con la del staging, el paquete anterior se respalda en `${XDG_CACHE_HOME:-~/.cache}/ravn-piloto/secrets-backups/secrets.tar.gz.age.bak-<fecha>` y recién entonces se hace un `mv` atómico. Los temporales se borran en cualquier salida (trap). Códigos de salida: 2 = pérdida de entradas, 3 = contraseña, 4 = verificación fallida.

   > **Salvaguarda contra pérdidas (issue #78):** antes de sobrescribir, el script descifra el paquete actual con la contraseña verificada y compara las listas `tar tz` de ambos paquetes. Si el nuevo tiene menos entradas o le falta alguna (p. ej. `.gnupg`, `.ssh`, `.grokbot`), las lista y aborta salvo que escribas `PERDER`; sin terminal aborta con código 2. Para una eliminación intencional sin terminal: `RECIFRAR_PERMITIR_PERDIDA=1`. Acepta `AGE_PASSPHRASE` para uso no interactivo (como `cifrar-secretos.sh` y `desbloquear-secretos.sh`). El export copia con `cp -a dir/.`, así que las carpetas ocultas sí llegan al staging. Test: `bash tests/secrets/test-export-staging-dotfiles.sh`.

4. **Versionar en Git (rama auxiliar ➔ PR ➔ merge):**
   ```bash
   git add scripts/secrets/secrets.tar.gz.age
   git commit -m "chore(secrets): update encrypted secrets bundle"
   ```

### Caso 2: Eliminar o Rotar un Secreto Obsoleto

1. Exporta el staging:
   ```bash
   ./desbloquear-secretos.sh --export-staging /tmp/staging-secrets
   ```
2. Elimina el archivo o carpeta que ya no deba existir:
   ```bash
   rm -rf /tmp/staging-secrets/nombre_del_secreto_a_eliminar
   ```
3. Si el secreto residía en usuarios del sistema, elimínalo de los perfiles gestionados y plantillas `/etc/skel/`.
4. Re-cifra el paquete:
   ```bash
   ./recifrar-interactivo.sh /tmp/staging-secrets
   ```
   *Como esto elimina entradas, la salvaguarda pedirá que escribas `PERDER` para confirmar.*

## ➕ Añadir la clave de firma del repo pacman al bundle (pendiente, 2026-10-27)

La clave nueva de `[omarchy-personal]` se generó en el box de Grok Bot y espera ahí en un archivo `0600`
(`/workspace/keys-backup/omarchy-personal-signing.asc`) hasta que
la metas en `secrets.tar.gz.age`. Como el bundle está cifrado con tu frase (`age -p`), solo vos podés hacerlo:

```bash
cd /z/PJ-NIRI-rf-omarchy-workstation/scripts/secrets
./desbloquear-secretos.sh --export-staging /tmp/staging-secrets   # pide tu frase
install -d -m700 /tmp/staging-secrets/omarchy-personal-repo
install -m600 ~/Descargas/omarchy-personal-signing.asc /tmp/staging-secrets/omarchy-personal-repo/signing-key.secret.asc
./recifrar-interactivo.sh /tmp/staging-secrets                    # pide la frase 2 veces (debe abrir el bundle actual), ofrece borrar el staging
./probar-descifrado.sh                                            # verificar
shred -u ~/Descargas/omarchy-personal-signing.asc
cd ../.. && git add scripts/secrets/secrets.tar.gz.age && git commit -m "secrets: clave de firma omarchy-personal-repo" && git push
```

Luego avisá para borrar la copia del box.
