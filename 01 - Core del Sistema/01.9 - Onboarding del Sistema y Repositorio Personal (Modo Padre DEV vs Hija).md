# 🚀 Onboarding del Sistema y Repositorio Personal (Modo Padre DEV vs Hija)

> [!NOTE]
> **Navegación de Capa:**
> * Anterior: [[01.8 - Usuario Sandbox Btrfs Desechable (sandbox)]]
> * Subir al Hub: [[01.0 - Core del Sistema (MOC)|📑 Hub de Capa 01]]
> * Índice Maestro: [[00.0 - Mapa General del Sistema (MOC)|🏠 Inicio (MOC)]]
> * Referencia Canónica: [Fork Docs — Onboarding de Máquinas](https://robert-flo.github.io/fork-docs/guide/02-onboarding-maquinas/)

Este módulo define la arquitectura formal, manual operativo y asistente automatizado para la **incorporación de cualquier máquina Arch Linux al ecosistema del Fork Personal de Omarchy** ([robert-flo/omarchy-personal-repo](https://github.com/robert-flo/omarchy-personal-repo) y [robert-flo/fork-docs](https://github.com/robert-flo/fork-docs)).

Cualquier computadora de la flota (laptop, workstation física o máquina virtual) puede ser provisionada bajo este procedimiento. El playbook **bifurca explícitamente su comportamiento** según el rol que asuma la máquina: **PADRE (Estación DEV)** o **HIJA (Máquina Cliente / Producción)**.

---

## 🧭 Principio Innegociable: Cero Clones en `$HOME` y Workspace Unificado en `/z/pj-omarchy`

En estricta concordancia con [[02.1 - Directorio Compartido (z) y Permisos ACL]], **ningún repositorio del sistema o del ecosistema de desarrollo debe clonarse dentro del `$HOME` de un usuario individual**:
1. Todos los repositorios de la flota se alojan agrupados bajo una sola carpeta raíz en el almacenamiento compartido: **`/z/pj-omarchy/`**.
2. Contiene el archivo de configuración multi-raíz **`pj-omarchy.code-workspace`**, permitiendo que cualquier usuario abra la totalidad del ecosistema en VSCode, Cursor o Google Antigravity IDE con un solo comando:
   ```bash
   code /z/pj-omarchy/pj-omarchy.code-workspace
   ```
3. Se mantienen enlaces simbólicos en `/z/fo-omarchy` y `/z/fork-docs` para preservar la compatibilidad con rutas fijas del sistema y el CLI `fork-docs`.
4. Todos los repositorios heredan permisos `2775` (setgid activo sobre el grupo `wheel`) y ACLs por defecto (`g:wheel:rwx`), permitiendo que cualquier usuario (`omarchy`, `niri`, `sura`, `nyxuri`) pueda colaborar e inspeccionar el código sin fricción de umask ni errores de titularidad dudosa en git (`safe.directory`).
5. El enlace de desarrollo en vivo (`omarchy dev link /z/fo-omarchy`) se registra a nivel global en `/etc/omarchy.conf` y `/etc/sudoers.d/omarchy-dev-path`, aplicando el entorno para todos los perfiles simultáneamente.

## 📊 Matriz Comparativa: Modo PADRE (DEV) vs. Modo HIJA (Cliente)

| Característica / Paso | Modo PADRE (Estación DEV) | Modo HIJA (Cliente / Producción) | Justificación Técnica |
| :--- | :--- | :--- | :--- |
| **Pregunta de Selección** | Obligatoria en el asistente CLI | Obligatoria en el asistente CLI | Un usuario `omarchy` puede existir en ambos roles; nunca se adivina por username (cualquier máquina puede asumir rol PADRE o HIJA). |
| **Clave GPG Pacman** | Importada y firmada (`76AFFCC217DB9FC4`) | Importada y firmada (`76AFFCC217DB9FC4`) | Ambos requieren confianza en los paquetes firmados del fork. |
| **Repositorio `[omarchy-personal]`** | Doble `Server` (Pages + Releases `pkg-stable`) | Doble `Server` (Pages + Releases `pkg-stable`) | Resuelve bases de datos y sortea el límite de 100 MB de GitHub Pages. |
| **Blindaje `IgnorePkg`** | **Obligatorio (`omarchy-dev omarchy-settings-dev`)** | No se aplica | Evita que `pacman -Syu` sobrescriba paquetes locales `dev.<sha>`. |
| **Ejecución de `omarchy update`** | **PROHIBIDA / Omitida** | **Obligatoria** | En Padre sobreescribiría árboles locales en desarrollo; en Hija instala `pkgrel=99+`. |
| **Aprovisionamiento `$HOME`** | **No forzado** (Protege checkout local) | **`omarchy provision user --force`** | En Hija materializa stubs en `~/.local/bin/` y launchers en `.desktop`. |
| **Soporte Multiusuario** | `/z/fo-omarchy` y `/z/fork-docs` para todos | Aprovisiona invocador + lista `--users` | Garantiza paridad en estaciones multi-perfil. |
| **Repositorio Fuente** | Clonado en `/z/fo-omarchy` (rama `personal`) | No requiere código fuente local | Solo la máquina DEV compila y edita el sistema base. |
| **Enlace de Desarrollo** | `omarchy dev link /z/fo-omarchy` | No aplica | Activa `$OMARCHY_PATH` en `/etc/omarchy.conf` para toda la máquina. |

## 🛠️ Procedimiento Automatizado con `omarchy-onboard`

El playbook proporciona el script canónico en `scripts/omarchy-onboarding/onboard-machine.sh` (ejecutable como asistente de onboarding; su empaquetado formal bajo pacman como `/usr/local/bin/omarchy-onboard` queda reservado a los tickets #18-#20).

### 1. Invocación Interactiva (Recomendada)
Al ejecutarse sin parámetros, el script despliega el menú interactivo para que el operador decida el rol:

```bash
sudo omarchy-onboard
```

```text
==========================================================================
         ONBOARDING DE MÁQUINA — ECOSISTEMA OMARCHY PERSONAL FORK         
==========================================================================
Cualquier computadora puede asumir rol PADRE o HIJA independientemente del
nombre de usuario configurado en ella.

Selecciona el rol que tendrá este equipo en la flota:

  1) PADRE (Estación de Desarrollo / Modo DEV)
     - No corre 'omarchy update' ciego (protege código local)
     - Blinda pacman con IgnorePkg = omarchy-dev omarchy-settings-dev
     - Aloja fo-omarchy en /z/fo-omarchy (2775 wheel) y corre 'dev link'
     - Habilita repositorio [omarchy-personal] firmado

  2) HIJA (Máquina Cliente / Producción)
     - Ejecuta los 7 pasos canónicos completos de fork-docs
     - Actualiza a paquetes sombreados (pkgrel=99+) con 'omarchy update'
     - Materializa launchers y stubs con 'omarchy provision user --force'
     - Reconcilia paquetes base ('omarchy reinstall pkgs') y espacios Herdr

==========================================================================
Ingresa tu opción [1 para Padre, 2 para Hija]: 
```

### 2. Invocación No Interactiva (Desatendida)

```bash
# Para incorporar una estación de desarrollo (Modo Padre):
sudo omarchy-onboard --padre

# Para incorporar una máquina cliente aprovisionando al usuario actual:
sudo omarchy-onboard --hija

# Para incorporar una máquina cliente multiusuario aprovisionando varios perfiles:
sudo omarchy-onboard --hija --users "omarchy niri nyxuri"

# Para auditar los cambios que se aplicarían sin modificar nada (Modo Simulación):
sudo omarchy-onboard --padre --dry-run
sudo omarchy-onboard --hija --dry-run
```

## 📋 Anatomía del Procedimiento Paso a Paso

### Etapa 1: Criptografía y Repositorio Pacman (Común a Ambos Roles)

#### 1. Importación y Firma de la Clave GPG del Repositorio
Se verifica la presencia de la clave RSA 4096-bit en el llavero local de pacman. Si no existe, se añade desde `/z/fork-docs/keys/omarchy-personal-repo.pub.asc` (o descarga remota) y se firma localmente:
```bash
sudo pacman-key --add /z/fork-docs/keys/omarchy-personal-repo.pub.asc
sudo pacman-key --lsign-key 76AFFCC217DB9FC4
```
*Huella digital canónica:* `CD92 AB07 B1D2 4DC9 A74E B60E 76AF FCC2 17DB 9FC4`.

#### 2. Inyección de `[omarchy-personal]` en `/etc/pacman.conf`
Se inyecta antes de `[omarchy]` con la configuración de doble servidor:
```ini
[omarchy-personal]
SigLevel = Required DatabaseOptional
Server = https://robert-flo.github.io/omarchy-personal-repo/stable/$arch
Server = https://github.com/robert-flo/omarchy-personal-repo/releases/download/pkg-stable
```
* *Server 1:* Resuelve `omarchy-personal.db` y paquetes < 100 MB alojados en GitHub Pages.
* *Server 2:* Resuelve paquetes pesados (> 100 MB, como `omarchy-4.0.6-100-any`) alojados en GitHub Releases tag `pkg-stable`.

#### 3. Sincronización de Bases de Datos
```bash
sudo pacman -Sy
```

### Etapa 2A: Flujo Exclusivo para Modo PADRE (DEV)

> [!WARNING]
> **Prohibición de `omarchy update` en Modo Padre:**
> La máquina de desarrollo contiene modificaciones activas en su árbol fuente. Ejecutar `omarchy update` desatendido descargaría versiones empaquetadas oficiales o sombreadas que sobrescribirían `/usr/share/omarchy/`, destruyendo el estado local de prueba.

1. **Inyección del Blindaje `IgnorePkg`:**  
   Evita que `pacman -Syu` sustituya los paquetes de prueba marcados como `dev.<commit-sha>`:
   ```ini
   # /etc/pacman.conf
   [options]
   ...
   HoldPkg = pacman glibc
   IgnorePkg = omarchy-dev omarchy-settings-dev
   ```
2. **Despliegue del Código Fuente en `/z/fo-omarchy`:**  
   Si no existe, se clona directamente en `/z/fo-omarchy` bajo la rama `personal`:
   ```bash
   git clone -b personal https://github.com/robert-flo/omarchy.git /z/fo-omarchy
   sudo chown -R $USER:wheel /z/fo-omarchy
   sudo chmod -R 2775 /z/fo-omarchy
   sudo find /z/fo-omarchy -type d -exec chmod g+s {} +
   sudo setfacl -R -m g:wheel:rwx /z/fo-omarchy
   sudo setfacl -R -d -m g:wheel:rwx /z/fo-omarchy
   git -C /z/fo-omarchy config core.fileMode false
   sudo git config --system --add safe.directory "/z/fo-omarchy"
   ```
3. **Activación del Modo Live (`omarchy dev link`):**  
   Configura `$OMARCHY_PATH="/z/fo-omarchy"` en `/etc/omarchy.conf` y genera `/etc/sudoers.d/omarchy-dev-path`:
   ```bash
   omarchy dev link /z/fo-omarchy
   ```
4. **Verificación de Desarrollo:**  
   ```bash
   omarchy dev status
   # Resultado esperado: dev-link: configured (/z/fo-omarchy)
   ```

---

### Etapa 2B: Flujo Exclusivo para Modo HIJA (Cliente)

1. **Actualización de la Distribución:**  
   Descarga e instala los paquetes sombreados (`pkgrel=99+`) desde el CDN:
   ```bash
   omarchy update
   ```
2. **Aprovisionamiento Forzado de Usuarios (`omarchy provision user --force`):**  
   Materializa en cada cuenta gestionada (`$HOME`):
   - Launchers `.desktop` en `~/.local/share/applications/`
   - Stubs de mise y wrappers en `~/.local/bin/` (ej. stub de `agy`)
   - Configuraciones en `~/.config/`
   - Stubs de `~/.bashrc` que cargan `/usr/share/omarchy/default/bash/rc`
3. **Reconciliación de Paquetes Base del Sistema:**  
   ```bash
   omarchy reinstall pkgs
   ```
4. **Siembra de Espacios Herdr:**  
   ```bash
   omarchy refresh herdr
   ```
5. **Verificación:**  
   ```bash
   pacman -Q omarchy omarchy-settings
   # Ambos deben reportar pkgrel >= 99 o -100
   ```

## 🔍 Verificación y Diagnóstico

Para comprobar en cualquier momento la salud de la integración:

```bash
# 1. Comprobar que pacman ve el repositorio personal
pacman -Sl omarchy-personal

# 2. Comprobar paquetes con blindaje en la máquina DEV
pacman -Qu
# Los paquetes dev deben mostrar: [ignored]

# 3. Comprobar permisos del almacenamiento compartido
ls -ld /z/fo-omarchy /z/fork-docs
# Salida esperada: drwxrwsr-x+ ... usuario wheel ...
```
