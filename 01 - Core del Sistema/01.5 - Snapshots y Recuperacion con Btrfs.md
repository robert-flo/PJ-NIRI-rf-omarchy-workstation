# 💾 Snapshots de `/home` con Btrfs (Almacenamiento Local y Externo)

> [!NOTE]
> **Navegación:**
> * Anterior: [[01.4 - Display Manager y Sesiones SDDM (Herald OS)|01.4 - Display Manager y Sesiones SDDM (Herald OS)]]
> * Siguiente: [[02.1 - Directorio Compartido (z) y Permisos ACL|02.1 - Directorio Compartido (z) y Permisos ACL]]
> * Volver a: [[00.0 - Mapa General del Sistema (MOC)|Índice General (MOC)]]

Este módulo documenta la estrategia de congelamiento de estado y recuperación ante desastres del sistema de archivos mediante **snapshots Btrfs** de solo lectura en disco interno y su replicación atómica hacia almacenamiento externo mediante flujos de `btrfs send | btrfs receive`.

---

## 🧭 Arquitectura de Almacenamiento

| Elemento | Configuración Típica | Rol |
|---|---|---|
| **Disco Interno** | Subvolumen Btrfs `@home` montado en `/home` | Sistema de archivos principal con soporte Copy-on-Write (CoW). |
| **Directorio de Usuarios** | Carpetas estándar dentro de `/home` | Se respaldan de forma consistente al tomar un snapshot de todo `@home`. |
| **Destino de Snapshots** | `/home/.snapshots/` | Almacén local instantáneo sin duplicación inicial de espacio. |
| **Disco Externo (Backup)** | Partición Btrfs externa (ej. `/run/media/$USER/EXTERNO`) | Destino para envíos completos e incrementales `btrfs send`. |

---

## 1️⃣ Creación del Snapshot Local (Solo Lectura)

Tomar un snapshot de solo lectura (`-r`) es una operación instantánea y es requisito obligatorio para poder usar `btrfs send`:

```bash
SNAPSHOT_NAME="home-$(date +%F)-backup"

sudo mkdir -p /home/.snapshots
sudo chmod 700 /home/.snapshots

# Crear snapshot de solo lectura de /home
sudo btrfs subvolume snapshot -r /home "/home/.snapshots/$SNAPSHOT_NAME"

# Verificar estado y flags
sudo btrfs subvolume show "/home/.snapshots/$SNAPSHOT_NAME" | grep -Ei "name|flags|creation"
```

> [!TIP]
> Un snapshot Btrfs es una operación atómica a nivel de bloques. Al crearse no consume espacio adicional; solo almacena los bloques que se modifiquen o eliminen a partir de ese instante.

---

## 2️⃣ Copia a Disco Externo (`btrfs send | btrfs receive`)

Para proteger la información contra fallos físicos del disco local, envía el flujo a una unidad externa formateada en Btrfs:

```bash
EXT_DIR="/run/media/$USER/ALMACEN_BTRFS/snapshots/home"
sudo mkdir -p "$EXT_DIR"

# Enviar snapshot mediante tubería binaria
sudo btrfs send "/home/.snapshots/$SNAPSHOT_NAME" | sudo btrfs receive "$EXT_DIR"

# Verificar integridad en el disco externo
sudo btrfs subvolume show "$EXT_DIR/$SNAPSHOT_NAME" | grep -Ei "name|received uuid|flags"
```

---

## 3️⃣ Copias Posteriores Incrementales (Alta Velocidad)

Si ya existe un snapshot previo en ambos discos, `btrfs send -p` transmite únicamente las diferencias a nivel de bloques:

```bash
PARENT_SNAPSHOT="home-2026-10-08-backup"  # Debe existir en ambos discos
NEW_SNAPSHOT="home-$(date +%F)-incremental"
EXT_DIR="/run/media/$USER/ALMACEN_BTRFS/snapshots/home"

# 1. Crear nuevo snapshot local
sudo btrfs subvolume snapshot -r /home "/home/.snapshots/$NEW_SNAPSHOT"

# 2. Enviar únicamente las diferencias delta
sudo btrfs send -p "/home/.snapshots/$PARENT_SNAPSHOT" "/home/.snapshots/$NEW_SNAPSHOT" | \
  sudo btrfs receive "$EXT_DIR"
```

*Las transferencias incrementales de 10-20 GB suelen tardar apenas unos segundos por USB 3.0.*

---

## 4️⃣ Creación de Copia Navegable en el Disco Externo

Los snapshots recibidos son de solo lectura (`ro=true`) y preservan los permisos de usuario originales. Si deseas explorar o recuperar archivos cómodamente desde cualquier cuenta:

```bash
EXT_BASE="/run/media/$USER/ALMACEN_BTRFS/snapshots"
TARGET_SNAP="$SNAPSHOT_NAME"

sudo mkdir -p "$EXT_BASE/navegable"
# Crear subvolumen escribible (sin -r) a partir del snapshot recibido
sudo btrfs subvolume snapshot "$EXT_BASE/home/$TARGET_SNAP" "$EXT_BASE/navegable/$TARGET_SNAP"

# Conceder permisos de lectura a cualquier usuario local con ACLs
sudo setfacl -R -P -m u::rwX,g::rwX,o::rwX,m::rwX "$EXT_BASE/navegable/$TARGET_SNAP"
sudo find "$EXT_BASE/navegable/$TARGET_SNAP" -type d -exec setfacl -d -m u::rwx,g::rwx,o::rwx,m::rwx {} +
```

---

## 5️⃣ Procedimiento de Restauración

### Restaurar un Directorio o Archivo Específico
```bash
S="/home/.snapshots/$SNAPSHOT_NAME/niri"
# Restaurar la configuración de niri
sudo cp -a "$S/.config/niri" /home/niri/.config/
```

### Restaurar el Home Completo de un Usuario
Asegúrate de que el usuario no tenga procesos abiertos (`sudo loginctl terminate-user niri`):

```bash
S="/home/.snapshots/$SNAPSHOT_NAME/niri"

# 1. Renombrar home dañado
sudo mv /home/niri /home/niri.antiguo

# 2. Restaurar usando reflink (instantáneo en el mismo sistema de archivos)
sudo cp -a --reflink=auto "$S" /home/niri

# 3. Comprobar permisos y eliminar respaldo temporal si todo está correcto
# sudo rm -rf /home/niri.antiguo
```

---

## 6️⃣ Mantenimiento y Eliminación de Snapshots Antiguos

Para liberar espacio retenido por bloques antiguos eliminados:

```bash
# Listar snapshots existentes
sudo btrfs subvolume list /home

# Eliminar snapshot local
sudo btrfs subvolume delete "/home/.snapshots/$SNAPSHOT_NAME"

# Eliminar snapshot del disco externo
sudo btrfs subvolume delete "$EXT_DIR/$SNAPSHOT_NAME"
```

> [!WARNING]
> Conserva siempre al menos un snapshot común entre ambos discos si planeas seguir realizando respaldos incrementales (`-p`).
