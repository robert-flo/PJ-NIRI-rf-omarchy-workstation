## 0. Lo único que hay que entender antes

- Un **Home Repo** (`HR-<X>`) es el repo donde vive el trío **PM/WK/RV-`HR-<X>`** de un proyecto que abarca varios repos ([Home Repo Pattern de aihero](https://www.aihero.dev/the-home-repo-pattern)). Es un **hijo de `robert-flo/pj-template`** en modo dependencia. El PM es la única puerta de entrada; los repos que supervisa se clonan **adentro** (ignorados por git).
- **En GitHub no vas a ver los agentes, y está bien.** El repo versiona solo ~13 archivos a mano (`proyecto.yml`, `AGENTS.md`, `README.md`, `.gitignore`, `./pj`, `.github/workflows/pj-template.yml`, `.trio/`, `CLAUDE.md`, `<HR>.code-workspace`, `docs/agents/*.md`). `.agents/` (agy), `.cursor/` (Cursor) y `.pj/` (template + venv) están en el `.gitignore` y **los genera `./pj listo` en cada máquina** desde pj-template al SHA de `template_ref`. **Sin `./pj listo`, agy y Cursor no ven ningún agente.**
- Clon canónico en la PC: `/z-home-repos/<HR>` ([[08.3 - Topologia Canonica de Repositorios, Worktrees y GitHub Workflows|08.3]]). Rama por defecto: `master`.
- Grok Bot (cloud) es otra isla: su trío se pide al CEO de Grok Bot y vive en `robert-flo/fleet`. Este runbook **no** lo toca y los archivos versionados del Home Repo **no** mencionan Grok Bot ni `robert-flo/fleet` (`./pj check` lo rechaza). Único puente: GitHub.

### Reglas que no se negocian

- Identidad de git `Roberto Flores <25asab015@ujmd.edu.sv>`. **Ningún commit lleva trailer ni firma de agente** (nada de `Co-authored-by:` ni `agente: … · plataforma: …`).
- Nunca commit directo a `master`: rama auxiliar → PR → RV `APRUEBO <sha>` sobre el head exacto → merge con `--squash --delete-branch --match-head-commit <sha>` sin esperar orden de Roberto ([ADR 0014 de pj-template](https://github.com/robert-flo/pj-template/blob/main/docs/adr/0014-el-pm-mergea-tras-apruebo.md)).
- `git pull --rebase --autostash` antes de trabajar y de empujar. Nunca `--force`. Nunca PRs a upstreams (omacom/omarchy, StatIndet).
- El token `PJ_TEMPLATE_TOKEN` nunca se imprime, nunca va en la línea de comandos ni en un archivo.
- Temporales en `~/.cache/ravn-piloto/`.

## A. Poner en marcha un Home Repo en una PC (`./pj listo`)

**Cuándo:** después de clonar un Home Repo, en una PC nueva o con otro usuario, o cuando agy/Cursor no muestran `PM-<HR>`. Corrélo **como el usuario que va a usar agy** (las fichas se enlazan en *su* `~/.gemini/config/agents`).

```bash
HR="HR-CLAVIS"                                   # el Home Repo
[ -d "/z-home-repos/$HR/.git" ] || gh repo clone "robert-flo/$HR" "/z-home-repos/$HR"
cd "/z-home-repos/$HR" && git switch master && ./pj listo
```

`./pj listo` hace, en orden: `git pull --rebase --autostash`, baja pj-template a `template_ref` en `.pj/tpl`, genera `.agents/` y `.cursor/`, instala los hooks `post-merge`/`post-checkout` (desde ahí **cada `git pull` regenera solo**), enlaza las fichas en `~/.gemini/config/agents`, clona los `repos:` de `proyecto.yml` y corre `./pj check`.

**Salida esperada** (real, clon limpio de HR-CLAVIS en `master` `7ce0030`, 2026-11-16):

```text

escrito .agents/agents/RV-HR-CLAVIS.md
escrito .cursor/rules/pm-hr-clavis.mdc

escrito .agents/reglas/wk.md

enlazado WK-HR-CLAVIS.md
```

«Nada que clonar» es normal mientras `repos: []` (antes del onboarding, paso B9). Una segunda corrida no escribe nada nuevo y termina igual en `check: todo bien`.

**Verificar que los agentes aparecen:**

```bash
cd "/z-home-repos/$HR"
hr=$(printf '%s' "$HR" | tr 'A-Z' 'a-z')
ls .agents/agents/                               # PM-$HR.md  RV-$HR.md  WK-$HR.md
ls .cursor/rules/ .cursor/agents/                # no-cursor-coauthor.mdc pm-$hr.mdc / rv-$hr.md wk-$hr.md

git status --short                               # vacío: nada generado entra a git
```

**Abrir:**

| Herramienta | Comando | Qué tenés que ver |
|---|---|---|
| agy (Antigravity) | `cd /z-home-repos/$HR && agy --agent PM-$HR` (o `./pj listo --abrir`) | El PM se presenta como `PM-<HR>`. WK y RV los lanza él. |
| Cursor IDE | `cursor /z-home-repos/$HR/$HR.code-workspace` | En *Cursor Settings → Rules* figura `pm-<hr>` (alwaysApply: el chat **es** el PM); `wk-<hr>` y `rv-<hr>` como subagentes en `.cursor/agents/`. |
| Cursor CLI | `cd /z-home-repos/$HR && cursor-agent` | Lee `AGENTS.md` y `.cursor/`; responde como el PM. |

Prueba de humo opcional con agy instalado: `./pj humo` (arranca el PM sin interacción y comprueba que responde con su nombre).

> [!TIP]
> **Otro usuario de la misma PC** (`niri`, `omarchy`, …): `cd /z-home-repos/$HR && ./pj agy` una vez en ese usuario. Los archivos generados ya están; solo faltan sus enlaces en su `~/.gemini`.

| Síntoma | Causa | Arreglo |
|---|---|---|
| agy/Cursor no ven `PM-<HR>`; no existe `.agents/` | No se corrió `./pj listo` tras clonar | Bloque de arriba. |
| `agy --agent PM-<HR>` arranca un agente genérico | Faltan los enlaces en `~/.gemini/config/agents` de **ese** usuario | `./pj agy` en ese usuario. |
| `pj: proyecto.yml no tiene template_ref` | Estás en una rama sin pj-template aplicado | `git switch master && ./pj listo`. |
| `pj: aviso: el pull falló` | Cambios locales en conflicto | Resolvé el conflicto y volvé a correr `./pj listo`. |
| `./pj check` con `FALLA` | Ver el mensaje; casi siempre un archivo generado versionado o un extra sin `git add` | Tabla de errores de [[#Errores conocidos al crear\|B]]. |

## B. Crear un Home Repo nuevo

Un solo agente corre B1→B9 en **una** sesión de shell (las variables de B1 se usan en todos los bloques). Si la sesión se corta, volvé a correr B1 y seguí desde el paso que falló.

> [!WARNING]
> **No uses `make nuevo-hijo`** de pj-template para un `HR-*`: crea `robert-flo/pj-<P>` (prefijo `pj-` forzado), con rama `main`, lo clona en `/z-drive/tries/rf-pj-<P>` y commitea **directo** a la rama por defecto. No crea `.trio/`, `CLAUDE.md`, workspace, `docs/agents/` ni etiquetas. Sirve solo para meta-repos `pj-*` que aceptan `main`.

### B1 — Variables y prerrequisitos

```bash
export HR="HR-EJEMPLO"           # nombre exacto: repo, carpeta y trío (PM-$HR, WK-$HR, RV-$HR)
export AREA="home repo de EJEMPLO — punto único de entrada del trío a todos sus repos"
export DEST="/z-home-repos/$HR"
export TPL="$HOME/.cache/ravn-piloto/pj-template"
export RAMA="ceo/aplicar-pj-template"
mkdir -p "$HOME/.cache/ravn-piloto"
[[ "$HR" =~ ^[A-Za-z0-9][A-Za-z0-9._-]*$ ]] && echo "nombre OK"
gh auth status 2>&1 | grep -q 'account robert-flo' && echo "gh OK"
stat -c '%a %G' /z-home-repos                    # 2770 wheel
command -v python3 git make gh jq >/dev/null && echo "herramientas OK"
```

**Verificación:** `nombre OK`, `gh OK`, `2770 wheel`, `herramientas OK`. Si falla uno, pará y avisale a Roberto cuál.

### B2 — Repo en GitHub (`master`), clon en `/z-home-repos` y rama auxiliar

```bash
gh repo view "robert-flo/$HR" >/dev/null 2>&1 \
  || gh repo create "robert-flo/$HR" --private --add-readme --description "Home repo $HR (hijo de pj-template)"
[ "$(gh repo view "robert-flo/$HR" --json defaultBranchRef --jq .defaultBranchRef.name)" = main ] \
  && gh api -X POST "repos/robert-flo/$HR/branches/main/rename" -f new_name=master >/dev/null
[ -d "$DEST/.git" ] || gh repo clone "robert-flo/$HR" "$DEST"
cd "$DEST"
git config user.name "Roberto Flores"; git config user.email "25asab015@ujmd.edu.sv"
git fetch -q origin && git switch master && git pull --rebase --autostash -q
if   git show-ref -q --verify "refs/heads/$RAMA"; then git switch "$RAMA"
elif git show-ref -q --verify "refs/remotes/origin/$RAMA"; then git switch -c "$RAMA" --track "origin/$RAMA"
else git switch -c "$RAMA"; fi
gh repo view "robert-flo/$HR" --json defaultBranchRef --jq .defaultBranchRef.name   # master
```

`--add-readme` deja el primer commit hecho **en GitHub**, así nadie commitea en `master` a mano. Si el repo ya existía y **no** es todavía hijo de pj-template (no tiene `./pj`), mirá la nota [[#Repo existente que todavía no es hijo de pj-template|repo existente]] antes de seguir.

### B3 — Template al SHA actual y archivos fijos

```bash
[ -d "$TPL/.git" ] || gh repo clone robert-flo/pj-template "$TPL" -- -q
git -C "$TPL" switch -q main && git -C "$TPL" pull -q --rebase --autostash
export SHA="$(git -C "$TPL" rev-parse HEAD)"
[ "$SHA" = "$(gh api repos/robert-flo/pj-template/commits/main --jq .sha)" ] && echo "template_ref = $SHA"
cd "$DEST"
git -C "$TPL" show "$SHA:plantillas/hijo/pj" > pj && chmod +x pj
mkdir -p .github/workflows
git -C "$TPL" show "$SHA:plantillas/hijo/pj-template.yml" > .github/workflows/pj-template.yml
grep -qxF '/rf-*/' .gitignore 2>/dev/null || git -C "$TPL" show "$SHA:plantillas/hijo/gitignore" >> .gitignore
grep -qxF "!$HR.code-workspace" .gitignore || printf '\n# Workspace del proyecto aunque esté en un gitignore global\n!%s.code-workspace\n' "$HR" >> .gitignore
```

**Verificación:** imprime `template_ref = <40 hex>`. No escribas a mano `/.pj/`, `/.agents/` ni `/.cursor/` en `.gitignore`: los agrega `./pj` en B5 dentro del bloque `# >>> $HR: repos (generado) >>>`.

### B4 — Archivos a mano

Copiá el bloque entero. Solo crea lo que falta; `template_ref` se pone siempre al SHA de B3.

### B5 — Generar el trío y pasar `./pj check`

```bash
cd "$DEST"
./pj                       # baja el template, genera .agents/ y .cursor/ y escribe el bloque generado de .gitignore
git add -A                 # seguro recién ahora: .gitignore ya ignora .pj/, .agents/ y .cursor/

git status --short | grep -E '^.. \.(pj|agents|cursor)/' && echo "MAL: hay generados en el índice" || echo "índice limpio"
```

**Verificación:** termina en `check: todo bien` (ninguna línea `FALLA`) e `índice limpio`. Existen `.agents/agents/{PM,WK,RV}-$HR.md`, `.cursor/rules/pm-<hr>.mdc`, `.cursor/agents/{wk,rv}-<hr>.md` (`<hr>` en minúsculas).

### B6 — 🙋 Secreto `PJ_TEMPLATE_TOKEN` y etiquetas

El secreto lo usa el job `sync` del workflow del hijo (PR diario que sube `template_ref`). Es el **mismo** PAT fine-grained de los otros hijos (`Contents`, `Pull requests`, `Workflows` en Read and write); si no incluye el repo nuevo, Roberto lo agrega en GitHub → Settings → Developer settings → Fine-grained tokens.

```bash
gh secret list -R "robert-flo/$HR" | grep -q PJ_TEMPLATE_TOKEN && echo "secreto OK" \
  || echo "🙋 Roberto: corré  gh secret set PJ_TEMPLATE_TOKEN -R robert-flo/$HR  (pide el valor oculto por stdin)"
bash "$DEST/.pj/tpl/scripts/etiquetas.sh" "robert-flo/$HR"
```

Si el agente no tiene un campo seguro para el token, **para** acá, le pasa a Roberto el comando que imprimió el bloque y sigue cuando `gh secret list` lo muestre. Nunca `echo` del token, nunca `--body <token>`, nunca un archivo.

**Verificación:** `secreto OK`; `etiqueta:` para `needs-triage`, `needs-info`, `ready-for-agent`, `ready-to-merge`, `wontfix` y `spec`.

### B7 — Commit, push y los dos PRs

```bash
cd "$DEST"
if ! ./pj check; then
  echo "B7: ./pj check en rojo; no se commitea ni se abre ningún PR. Volvé a B5." >&2
else
  git add -A
  git diff --cached --quiet || git commit -q -m "feat(home-repo): aplicar pj-template a $HR" \
    -m "$HR pasa a ser home repo hijo de robert-flo/pj-template en modo dependencia (template_ref ${SHA:0:7}, rama_base master, repos y specs vacíos hasta el onboarding del PM). ./pj listo genera PM/WK/RV-$HR para agy y Cursor."
  git log -1 --format=%B | grep -niE 'co-authored-by|^agente:|plataforma:' && echo "HAY TRAILER: ver abajo, no empujes" || {
    git pull --rebase --autostash -q origin master
    git push -q -u origin HEAD
    gh pr view --json url --jq .url 2>/dev/null || gh pr create -R "robert-flo/$HR" --base master \
      --title "feat(home-repo): aplicar pj-template a $HR" \
      --body "Aplica robert-flo/pj-template (modo dependencia) a $HR con el runbook 08.7 del vault workstation. Versiona solo los archivos a mano; .pj/, .agents/ y .cursor/ los genera ./pj listo. repos: vacío hasta el onboarding."
    # family.yml de pj-template: notify-children avisa a los hijos registrados cuando cambia el template.

    if grep -qx "  - robert-flo/$HR" family.yml; then echo "ya registrado en family.yml"
    elif gh pr list -R robert-flo/pj-template --head "family/$HR" --state open --json url --jq '.[0].url' | grep .; then :
    else
      git switch -q -C "family/$HR" main
      printf '  - robert-flo/%s\n' "$HR" >> family.yml
      git commit -q -am "chore(family): agregar $HR a los hijos"
      git push -q -u origin "family/$HR"
      gh pr create -R robert-flo/pj-template --base main --head "family/$HR" \
        --title "chore(family): agregar $HR a los hijos" --body "Home repo $HR aplicado por PR en robert-flo/$HR (runbook 08.7)."

  }

```

Si el entorno inyectó un trailer y el commit **todavía no se empujó**, rehacelo sin él: `git reset --soft HEAD~1 && git update-ref "refs/heads/$(git branch --show-current)" "$(git commit-tree "$(git write-tree)" -p HEAD -m "feat(home-repo): aplicar pj-template a $HR")"`. Si ya se empujó, no se reescribe (sería `--force`): commit nuevo.

**Verificación:** dos URLs de PR (el de `robert-flo/$HR` contra `master`; el de pj-template contra `main` con un diff de una línea). `gh pr checks` del primero: el job `check` en verde.

### Errores conocidos al crear

| Síntoma | Causa | Solución |
|---|---|---|
| `./pj check`: «archivos versionados que deberían venir de pj-template: X» | Archivo propio fuera de `.agents/`, `.cursor/`, `.pj/` que no está en `extras:`; o algo versionado **bajo** esos dirs | Sumalo a `extras:`; si está bajo un dir generado, `git rm --cached` (no va en `extras:`). |
| `./pj check`: «extras: X no está versionado» | Falta `git add` | `git add -A` (B5). |
| `./pj check`: «… es generado y no debe versionarse» | Un generado entró al índice (un `git add -A` antes de `./pj`) | `git rm -r --cached --ignore-unmatch -q .agents .cursor .pj` y `./pj`. |
| `./pj check` rechaza `grok bot` / `robert-flo/fleet` | Mención en un archivo versionado | Sacarla; Grok Bot es otra isla. |
| `./pj` falla por «datos del molde» o un valor cortado | `proyecto.yml` con datos de pj-template o un `#` sin comillas | Corregí `proyecto.yml` (B4). |
| No llegan PRs de sync / falla el job `sync` | Falta el secreto o el PAT no incluye el repo | B6. |
| El `.code-workspace` no aparece en `git status` | Gitignore global ignora `*.code-workspace` | Línea `!<HR>.code-workspace` (B3). |

## Pendientes conocidos (fuera de este runbook)

> [!WARNING]
> - **No hay un comando único en pj-template para un `HR-*`.** `make nuevo-hijo` asume `pj-<P>`, `main`, `/z-drive/tries/rf-pj-<P>` y commit directo (ver aviso de B). El arreglo propuesto es parametrizar `nuevo-hijo.sh` (nombre sin prefijo forzado, `rama_base: master`, clon en `/z-home-repos/<HR>`, rama + PR en vez de push directo, `.trio/`, `CLAUDE.md`, workspace, `docs/agents/`, etiquetas y `./pj listo` al final), para que B1–B7 sean `make nuevo-home-repo HR=<X>`. Hasta entonces manda esta nota.
> - **`pj-trio` no busca en `/z-home-repos`.** Resuelve el proyecto por nombre en `$PJ_TRIO_ROOT`, el padre de `$PWD` o `/z-drive/tries`, y si no lo encuentra **clona otra copia** con try-clone. Con un `HR-*` pasale la ruta (`pj-trio /z-home-repos/<HR> …`) o exportá `PJ_TRIO_ROOT=/z-home-repos`. Arreglo en ravn-trio.
> - **La confianza de agy** (`trustedWorkspaces`) que ravn-trio atribuye a la workstation solo nombra `/z-drive/tries`; en `/z-home-repos` agy muestra «Do you trust the contents of this project?» la primera vez. Ningún repo de robert-flo la configura todavía.
> - **ravn-sessionizer** (`ri`, `rs`, `prefix+t`) filtra con `^pj-` y no ve los `HR-*`.
> - `pj-omarchy` vive en `/z/pj-omarchy`, no en `/z-home-repos/` como pide [[08.3 - Topologia Canonica de Repositorios, Worktrees y GitHub Workflows|08.3]]; 08.3 y `proyectos/forkhub.md` todavía citan `/z-home-repos/PJ-CLAVIS` (hoy HR-CLAVIS). Migración y renombre pendientes de orden de Roberto.
