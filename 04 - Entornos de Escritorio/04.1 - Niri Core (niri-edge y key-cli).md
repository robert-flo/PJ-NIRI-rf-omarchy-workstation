Este módulo documenta el despliegue a nivel de sistema del compositor base **`niri-edge`** (fork de Niri con soporte nativo de minimización y bordes pulidos) y el runtime CLI complementario **`key-cli`**, compilados e instalados desde sus forks en GitHub sobre **Arch Linux / Omarchy**.

---

## 📦 Repositorios y Fuentes Upstream

| Componente | Fuente (`origin`) | Rama | Upstream (`upstream`, solo lectura) | Rol en el Entorno |
|---|---|---|---|---|
| **niri-edge** | [robert-flo/PJ-NIRI-fo-niri-edge](https://github.com/robert-flo/PJ-NIRI-fo-niri-edge) | `personal` | [StatIndet/niri-edge](https://github.com/StatIndet/niri-edge) | Compositor Wayland con soporte nativo de minimización y bordes redondeados/rectangulares. |
| **key-cli** | [robert-flo/PJ-NIRI-fo-key-cli](https://github.com/robert-flo/PJ-NIRI-fo-key-cli) | `personal` | [StatIndet/key-cli](https://github.com/StatIndet/key-cli) | Daemon complementario de Clavis Shell (IPC, métricas de hardware nativas, clipboard). Incluye `key clipboard --daemon`. |

> [!IMPORTANT]
> **Fuente = mis forks, rama `personal`.** Ahí residen las modificaciones propias (por ejemplo, `key clipboard --daemon`), y el workflow `sync-personal-fork` de cada fork sincroniza los cambios de StatIndet. `upstream` se configura solo para lectura, con el push deshabilitado.
> **Regla: nunca abrir PRs a StatIndet** (no aceptan contribuciones asistidas por IA). Los cambios entran por PR a `personal` del fork correspondiente.

## 🛠️ Dependencias del Sistema

Instalar las herramientas de compilación y librerías de soporte requeridas vía `pacman`:

```bash
sudo pacman -S --needed --noconfirm \
  rust cargo clang cmake ninja qt6-base base-devel \
  waybar fuzzel alacritty mako swaybg swaylock xwayland-satellite \
  xdg-desktop-portal-gnome polkit-gnome wl-clipboard brightnessctl playerctl \
  cliphist libqalculate python-evdev python-pyudev gpu-screen-recorder slurp ffmpeg libpulse
```

> [!NOTE]
> `pactl` no es un paquete independiente en Arch Linux: el comando lo provee `libpulse`. Incluir `pactl` en la lista hace que `pacman` aborte toda la transacción con `target not found`.

## 🔧 Proceso de Instalación Paso a Paso

### 1. Compilación y Despliegue de `niri-edge`

```bash
# Directorio de trabajo de compilación centralizado
BUILD_DIR="${BUILD_DIR:-/opt/src}"
sudo mkdir -p "$BUILD_DIR"
sudo chown "$USER:$USER" "$BUILD_DIR"

# 1. Clonar o actualizar el repositorio
cd "$BUILD_DIR"
if [ ! -d "niri-edge" ]; then
    git clone -b personal https://github.com/robert-flo/PJ-NIRI-fo-niri-edge.git niri-edge
    git -C niri-edge remote add upstream https://github.com/StatIndet/niri-edge.git
    git -C niri-edge remote set-url --push upstream DISABLE
    cd niri-edge
else
    cd niri-edge
    git switch personal
    git pull --ff-only
fi

# 2. Compilar binario en release utilizando el git del sistema
CARGO_NET_GIT_FETCH_WITH_CLI=true cargo build --release

# 3. Desplegar ejecutables en /usr/local/bin y enlaces simbólicos
sudo install -Dm755 target/release/niri /usr/local/bin/niri
sudo ln -sf /usr/local/bin/niri /usr/bin/niri
sudo install -Dm755 resources/niri-session /usr/local/bin/niri-session
sudo ln -sf /usr/local/bin/niri-session /usr/bin/niri-session

# 4. Registrar sesión Wayland para Display Managers (SDDM)
sudo install -Dm644 resources/niri.desktop /usr/share/wayland-sessions/niri.desktop
sudo install -Dm644 resources/niri.desktop /usr/local/share/wayland-sessions/niri.desktop

# 5. Instalar configuración de portales XDG (capturas y screen-sharing)
sudo install -Dm644 resources/niri-portals.conf /usr/share/xdg-desktop-portal/niri-portals.conf
sudo install -Dm644 resources/niri-portals.conf /usr/local/share/xdg-desktop-portal/niri-portals.conf

# 6. Unidades systemd de sesión para usuarios
sudo install -Dm644 resources/niri.service /usr/lib/systemd/user/niri.service
sudo install -Dm644 resources/niri-shutdown.target /usr/lib/systemd/user/niri-shutdown.target

# 7. Autocompletados de shell
sudo mkdir -p /usr/share/bash-completion/completions /usr/share/zsh/site-functions /usr/share/fish/vendor_completions.d
target/release/niri completions bash | sudo tee /usr/share/bash-completion/completions/niri > /dev/null
target/release/niri completions zsh | sudo tee /usr/share/zsh/site-functions/_niri > /dev/null
target/release/niri completions fish | sudo tee /usr/share/fish/vendor_completions.d/niri.fish > /dev/null
sudo chmod 644 /usr/share/bash-completion/completions/niri /usr/share/zsh/site-functions/_niri /usr/share/fish/vendor_completions.d/niri.fish

# 8. Recargar configuraciones de systemd
sudo systemctl --system daemon-reload
```

### 2. Instalación de `key-cli` y Capacidades de Hardware

`key-cli` cuenta con su instalador (`scripts/install.sh`) que crea un entorno Python virtual aislado en `/usr/local/lib/key-cli/venv/`, compila el monitor nativo en C++ (`key-sysmon`) y el lector de energía (`key-cpu-power`).

```bash
cd "$BUILD_DIR"
if [ ! -d "key-cli" ]; then
    git clone -b personal https://github.com/robert-flo/PJ-NIRI-fo-key-cli.git key-cli
    git -C key-cli remote add upstream https://github.com/StatIndet/key-cli.git
    git -C key-cli remote set-url --push upstream DISABLE
    cd key-cli
else
    cd key-cli
    git switch personal
    git pull --ff-only
fi

# 1. Instalación base (como TU usuario, nunca con sudo: el instalador se eleva solo)
/usr/bin/python3 scripts/installer.py

# 2. HABILITACIÓN 1: Regla udev para eventos de teclado (Caps / Num Lock)
/usr/bin/python3 scripts/installer.py --keyboard enable --acknowledge-keyboard-access --apply

# 3. HABILITACIÓN 2: Lectura de energía CPU (RAPL) sin root
sudo setcap 'cap_dac_read_search=ep' /usr/local/libexec/key-cli/key-cpu-power

# 4. HABILITACIÓN 3: Autocompletados de shell (Fish)
sudo install -Dm644 completions/key.fish /usr/share/fish/vendor_completions.d/key.fish
```

> [!CAUTION]
> **Nunca `sudo /usr/bin/python3 scripts/installer.py`.** El instalador realiza dos trabajos: el despliegue de sistema en `/usr/local/` (para el que llama a `sudo` por su cuenta) y la configuración de servicios de usuario (`systemctl --user`), que pertenecen a quien lo ejecuta. Como root, esa segunda parte iría al usuario root y fallaría.
> Cada reinstalación de `key-cli` reemplaza `key-cpu-power` y borra su capacidad; es necesario repetir el `setcap` tras reinstalar.

### 3. `key clipboard --daemon` (Fork Propio, Rama `personal`)

`key-cli` de StatIndet original no incluye `key clipboard --daemon`. Mi fork lo incorpora ([PR #1 del fork](https://github.com/robert-flo/PJ-NIRI-fo-key-cli/pull/1)):

| Situación | Qué hace `key clipboard --daemon` |
|---|---|
| Ya hay un watcher con el lock de `$XDG_RUNTIME_DIR/key/clipboard-watch.lock` | Nada; sale con código 0 (`clipboard watcher already running`). |
| Existe `clavis-clipboard.service` y puede arrancar | Inicia `clavis-clipboard.service`; systemd sigue siendo el dueño del watcher. |
| No hay servicio o no puede arrancar | Lanza `key clipboard watch` en segundo plano en su propia sesión. |

```bash
# Verificación de funcionamiento
key clipboard --help | head -2
key clipboard --daemon
```

## 🔍 Pasos de Verificación y Diagnóstico

```bash
# 1. Validar versión de niri
niri --version

# 2. Diagnóstico general de key-cli
key doctor --json
# Debe retornar "ok": true y "missing": []

# 3. Acceso a eventos de teclado
key keyboard status --format json
# Debe responder: "available": true

# 4. Lectura de energía CPU (RAPL)
key sysmon cpu --format json
# "powerWatts" debe retornar un valor numérico real positivo
```
