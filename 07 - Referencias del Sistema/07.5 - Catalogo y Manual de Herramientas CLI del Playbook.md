## 1. 🔄 Sincronización y Almacenamiento Cloud (Suite synchub y sync-*)

### 1.1 `synchub` — CLI Maestro de Respaldos y Sincronización Declarativa
* **Ruta de destino:** `/usr/local/bin/synchub`
* **Definiciones modulares:** `/etc/synchub/targets.d/*.conf`
* **Directorio de logs y estado:** `/z-drive/.sync-state/`
* **Nota arquitectónica:** [[02.4 - Suite Declarativa synchub y Automatizacion Udev]]

CLI maestro multi-objetivo con soporte para simulación (`--dry-run`), protección contra borrado masivo (*Escudo de Seguridad*), rotación GFS de snapshots Btrfs CoW y apagado automático tras respaldo.

```text
Uso:
  synchub [COMANDO] [OBJETIVO] [OPCIONES]

Comandos principales:
  status                 Muestra el dashboard global de salud, discos y carpetas.
  sync [target|--all]    Ejecuta la sincronización de un objetivo o de todos.
  add <nombre>           Asistente interactivo para añadir una nueva carpeta colaborativa.
  remove <nombre>        Desmonta y elimina la configuración de un objetivo.
  prune-snapshots        Ejecuta la política de retención GFS en snapshots Btrfs.
  targets                Lista todos los objetivos configurados.

Opciones de sincronización (para 'synchub sync'):
  -n, --dry-run          Modo simulación: no modifica archivos locales ni remotos.
  -c, --copy             Modo copia acumulativa: no elimina archivos en destino.
  -l, --local-only       Sincroniza únicamente hacia el disco local Btrfs.
  -r, --cloud-only       Sincroniza únicamente hacia la nube (Google Drive).
  --pull                 Descarga / restaura desde la nube hacia el disco local.
  --force-delete         Autoriza borrado masivo si se supera el umbral de seguridad (30%).
  --poweroff, --shutdown Apaga el sistema automáticamente tras finalizar con éxito.
  -h, --help             Muestra esta ayuda.
```

#### Ejemplos de Casos de Uso:
```bash
# 1. Inspeccionar el estado global de sincronización y discos
synchub status

# 2. Sincronizar únicamente la carpeta 'tries' hacia la nube y Btrfs
synchub sync tries

# 3. Simular la sincronización de todo sin alterar datos
synchub sync --all --dry-run

# 4. Sincronizar todo al finalizar la jornada de trabajo y apagar la máquina
synchub sync --all --poweroff

# 5. Agregar una nueva carpeta colaborativa al ecosistema
sudo synchub add proyectos
```

* **Ruta:** `/usr/local/bin/sync-status`
* **Propósito:** Muestra un informe condensado del estado de cada carpeta colaborativa (`tries`, `idalia`, `uploads-gracie`, `boveda`) leyendo directamente los logs y marcas temporales en `/z-drive/.sync-state/`.

```bash
# Ejecución rápida:
sync-status
```

### 1.3 `sync-all`, `sync-tries`, `sync-idalia`, `sync-uploads-gracie`
* **Rutas:** `/usr/local/bin/sync-all`, `/usr/local/bin/sync-tries`, etc.
* **Propósito:** Scripts ejecutables individuales para sincronización directa o invocación desde atajos de teclado y lanzadores de escritorio.

## 2. 🍴 Gestión de Flota de Forks y Repositorios (forkhub)

### 2.1 `forkhub` — Motor de Idempotencia y Actualización de Flota
* **Ruta de destino:** `/usr/local/bin/forkhub`
* **Definiciones modulares:** `/etc/forkhub/repos.d/*.conf`
* **Log del sistema:** `/var/log/forkhub.log`
* **Temporizador systemd:** `forkhub.timer` (diario a las 04:30 AM)
* **Nota arquitectónica:** [[07.2 - Repositorios Upstream y Fuentes Externas]]

Gestiona y audita el estado de todos los repositorios clonados o forks mantenidos en el sistema. Realiza comprobaciones automáticas con los remotos upstream; si no hay cambios, no realiza escrituras innecesarias. Si existen commits nuevos, realiza un *fast-forward* limpio, ejecuta hooks post-actualización y envía una notificación visual al escritorio Wayland activo.

```text
Uso:
  forkhub [COMANDO] [OBJETIVO] [OPCIONES]

Comandos principales:
  status                       Muestra el dashboard global de repositorios y forks.
  update [repo|--all]          Actualiza idempotentemente los repositorios configurados.
  add <nombre> <ruta>          Registra un nuevo repositorio o fork en la flota.
  remove <nombre>              Retira un repositorio de la flota (no borra archivos).
  list / repos                 Lista los repositorios registrados y sus rutas.

Opciones de actualización (para 'forkhub update'):
  -n, --dry-run                Modo simulación: consulta remotos sin alterar árboles locales.
  -g, --group <grupo>          Actualiza únicamente repositorios del grupo indicado (ej. 'neovim').
  -a, --all                    Actualiza todos los repositorios con auto_update activado (por defecto).
  -f, --force                  Fuerza el fetch/check incluso si hay advertencias previas.
  -h, --help                   Muestra esta ayuda.
```

#### Ejemplos de Casos de Uso:
```bash
# 1. Ver el dashboard con la salud y versiones de toda la flota
forkhub status

# 2. Actualizar únicamente las distribuciones de Neovim
forkhub update --group neovim

# 3. Comprobar si hay actualizaciones sin aplicar cambios (dry-run)
forkhub update --all --dry-run

# 4. Registrar un nuevo fork en la flota para monitoreo diario
sudo forkhub add nyxuri /z/nyxuri personal origin shell

# 5. Retirar un repositorio de la flota
sudo forkhub remove test-repo -f
```

## 3. 🖋️ Suite de Edición de Texto y Desarrollo (Neovim)

El sistema dispone de tres distribuciones de Neovim compartidas en `/z/nvims/` y resueltas de forma nativa mediante la variable `NVIM_APPNAME` y `XDG_CONFIG_DIRS="/z/nvims"`, eliminando por completo los enlaces simbólicos en `$HOME/.config/` y `/etc/skel/`. El almacenamiento `/z/nvims` pertenece a `omarchy:wheel` (`2775`) y es vigilado por `z-perms.service`, permitiendo editar las configuraciones directamente sin `sudo`.

### Resumen de Comandos:

| Comando | Distribución Asociada | `NVIM_APPNAME` | Rol en el Sistema |
|---|---|---|---|
| `nvim` | **`rvim` (Roberto Flores)** | *(por defecto)* | **Editor principal predeterminado**. Utilizado para programación diaria, Git commits y llamadas de `$EDITOR`. |
| `rvim` | **`rvim` (Roberto Flores)** | `rvim` | Acceso directo explícito a la distro personal con persistencia retrocompatible. |
| `cvim` / `craftvim` | **Craftzdog IDE** | `cvim` | Entorno IDE completo con `vim.pack`, Solarized Osaka, Snacks UI y exploradores avanzados. |
| `2kvim` | **nvim2k (2KAbhishek)** | `2kvim` | Entorno minimalista y ligero con iconos y plugins de productividad rápida. |

#### Casos de Uso:
```bash
# Abrir un archivo con tu editor predeterminado rápido (rvim)
nvim main.py

# Abrir el proyecto en el entorno gráfico completo de Craftzdog
cvim .
craftvim .

# Abrir en la distribución secundaria nvim2k
2kvim README.md
```

## 4. 🔐 Seguridad, Secretos y Criptografía (age)

Scripts ubicados en la raíz del playbook (`/z/PJ-NIRI-rf-omarchy-workstation/scripts/` o directamente en el vault) para la custodia hermética de claves SSH, tokens de GitHub, credenciales Rclone y llaves GPG mediante `age`.

* **Nota arquitectónica:** [[01.6 - Gestion de Secretos y Llaves Cifradas (age)]]

### 4.1 `probar-descifrado.sh` — Prueba de Integridad en RAM Volátil
* **Propósito:** Solicita tu passphrase maestra, descifra el archivo `secretos-omarchy.tar.gz.age` exclusivamente en un disco en RAM (`tmpfs`), valida que el tarball contenga todos los archivos requeridos y libera la memoria de inmediato. **Cero persistencia en disco**.

```bash
cd /z/PJ-NIRI-rf-omarchy-workstation
./probar-descifrado.sh
```

### 4.2 `desbloquear-secretos.sh` — Aprovisionamiento de Nueva Máquina
* **Propósito:** Diseñado para ejecutarse durante el bootstrap de un nuevo equipo Arch Linux. Descifra los secretos y los restaura en sus ubicaciones definitivas en `$HOME` (`~/.ssh`, `~/.config/rclone/`, `~/.gnupg/`, etc.) con permisos estrictos (`0700` / `0600`).

```bash
./desbloquear-secretos.sh
```

### 4.3 `recifrar-interactivo.sh` — Asistente de Actualización de Secretos
* **Propósito:** Guía interactiva paso a paso para añadir nuevas credenciales o actualizar tokens existentes, empaquetando y cifrando el nuevo paquete `.age` listo para versionar en Git.

```bash
./recifrar-interactivo.sh
```

### 6.1 `fix_shared_dir_perms.sh` — Reparador Recursivo de Permisos
* **Ruta:** `/usr/local/bin/fix_shared_dir_perms.sh`
* **Nota arquitectónica:** [[02.1 - Directorio Compartido (z) y Permisos ACL]]

Asegura que todos los archivos y subdirectorios dentro de `/z/`, `/z-drive/`, `/opt/android-sdk/` y `/z/android-projects/` mantengan pertenencia al grupo `wheel`, el bit `setgid` (2775 / 2770) y las ACLs heredables para que cualquier usuario del sistema pueda leer y escribir sin fricción.

```bash
# Reparación general de permisos en almacenamiento colaborativo:
sudo fix_shared_dir_perms.sh
```

### 6.2 Vigilantes en Tiempo Real (`*_watcher.sh`)
* **Demonios:** `z_watcher.sh`, `android_sdk_watcher.sh`, `android_projects_watcher.sh`, `z_drive_watcher.sh`

## 7. 🛡️ Confinamiento y Sandbox Amnésico (guest y sandbox)

### 7.1 `guest-session-manager.sh` — Control del `$HOME` Volátil en RAM
* **Ruta:** `/usr/local/bin/guest-session-manager.sh`
* **Plantilla limpia:** `/etc/guest-skel/`
* **Nota arquitectónica:** [[01.7 - Usuario Especial Amnesico y Sandbox (guest)]]

Gestiona la vida de la sesión amnésica para el usuario `guest`. Es invocado automáticamente por PAM en login y logout, pero también puede operarse interactivamente por el administrador para auditoría y pruebas:

```text
Uso:
  guest-session-manager.sh [COMANDO]

Comandos:
  status                 Muestra si /home/guest está actualmente montado en RAM y el espacio ocupado.
  start / mount          Monta el tmpfs de 8GB en /home/guest y sincroniza la plantilla limpia.
  stop / umount          Mata procesos residuales de guest y desmonta la RAM (borrado total).
  reset                  Reinicia el entorno a estado de fábrica inmediatamente.
```

#### Ejemplos de Casos de Uso:
```bash
# 1. Comprobar si hay una sesión activa de guest y memoria en uso
sudo guest-session-manager.sh status

# 2. Resetear el sandbox de fábrica manualmente
sudo guest-session-manager.sh reset

# 3. Forzar el desmontaje y liberación inmediata de memoria RAM
sudo guest-session-manager.sh stop
```

---

### 7.2 `sandbox-btrfs-manager.sh` — Rollback Instantáneo CoW para Btrfs
* **Ruta:** `/usr/local/bin/sandbox-btrfs-manager.sh`
* **Plantilla dorada:** `/home/.sandbox-golden`
* **Nota arquitectónica:** [[01.8 - Usuario Sandbox Btrfs Desechable (sandbox)]]

Gestiona el ciclo de vida del subvolumen desechable `/home/sandbox`. Al cerrar sesión o ejecutarse manualmente, borra el subvolumen modificado y toma un snapshot nuevo desde la plantilla dorada en 1 milisegundo:

```text
Uso:
  sandbox-btrfs-manager.sh [COMANDO]

Comandos:
  status                 Muestra si /home/sandbox es un subvolumen activo y el espacio ocupado.
  reset / rollback       Destruye el subvolumen actual y restaura un snapshot nuevo en 1 ms.
```

#### Ejemplos de Casos de Uso:
```bash
# 1. Auditar estado del subvolumen Btrfs y espacio disponible
sudo sandbox-btrfs-manager.sh status

# 2. Forzar rollback instantáneo CoW a estado de fábrica
sudo sandbox-btrfs-manager.sh reset
```

## 8. 🌐 Portal Documental y Estándar de Oro (fork-docs)

### 8.1 `fork-docs` — Asistente Global del Ecosistema Omarchy Personal
* **Ruta de destino:** `/usr/local/bin/fork-docs`
* **Directorio compartido:** `/z/fork-docs`
* **Portal online:** `https://robert-flo.github.io/fork-docs/`
* **Nota arquitectónica:** [[03.6 - Ecosistema Omarchy Personal Fork y Portal fork-docs]]

Herramienta global multiusuario para la consulta, inspección, compilación y servicio local del portal de documentación canónica ("Estándar de Oro") del fork personal de Omarchy y sus ADRs.

```text
Uso:
  fork-docs [COMANDO]

Comandos principales:
  open           Abre la documentación en el navegador (local si está activa, o remota).
  serve          Inicia el servidor local Jekyll en segundo plano o interactivo (puerto 4000).
  build          Compila el sitio estático en /z/fork-docs/_site.
  status         Comprueba el estado de /z/fork-docs y de los paquetes en pacman.
  update / pull  Actualiza el repositorio /z/fork-docs con upstream (git pull --ff-only).
  path           Muestra la ruta canónica del repositorio (/z/fork-docs).
  help           Muestra esta ayuda.
```

#### Ejemplos de Casos de Uso:
```bash
# 1. Comprobar la sincronización del repositorio y paquetes del par personal
fork-docs status

# 2. Abrir la documentación en el navegador predeterminado
fork-docs open

# 3. Iniciar el servidor local para desarrollo o consulta sin conexión
fork-docs serve

# 4. Compilar estáticamente el portal con Jekyll
fork-docs build
```

### 8.2 `omarchy-onboard` — Asistente de Onboarding de Máquinas (Padre DEV vs Hija)
* **Ruta de destino:** `/usr/local/bin/omarchy-onboard` (symlink a la fuente)
* **Script fuente canónico:** `scripts/omarchy-onboarding/onboard-machine.sh`
* **Notas arquitectónicas:** [[01.9 - Onboarding del Sistema y Repositorio Personal (Modo Padre DEV vs Hija)]] y [[docs/adr/0001-una-sola-puerta-y-meta-workspace|ADR 0001]].

Asistente interactivo e idempotente para incorporar cualquier máquina Arch Linux a la flota del Fork Personal de Omarchy. Pregunta obligatoriamente al operador si el equipo operará en modo **PADRE (DEV)** o **HIJA (Cliente de Producción)**. En modo PADRE, alinea el meta-workspace [[docs/adr/0001-una-sola-puerta-y-meta-workspace|/z/pj-omarchy]] mediante `./pj listo` y preserva los symlinks de compatibilidad `/z/fo-omarchy` y `/z/fork-docs`.

```text
Uso:
  sudo omarchy-onboard [OPCIONES]

Opciones principales:
  --padre, --dev        Configura la máquina como Estación de Desarrollo (Modo DEV)
                        - Blinda pacman con IgnorePkg = omarchy-dev omarchy-settings-dev
                        - Despliega y alinea /z/pj-omarchy vía ./pj listo y ejecuta dev link
                        - Omite 'omarchy update' desatendido y provision forzado
  --hija, --client      Configura la máquina como Cliente de Producción (Modo Hija)
                        - Ejecuta ciclo de 7 pasos canónicos
                        - Actualiza paquetes sombreados (pkgrel=99+) con 'omarchy update'
                        - Materializa configs en $HOME con 'omarchy provision user --force'
                        - Reconcilia paquetes base del sistema con 'omarchy reinstall pkgs'
  --users "<u1 u2...>"  Lista adicional de usuarios a aprovisionar en Modo Hija
  -n, --dry-run         Modo simulación: no modifica archivos del sistema
  -h, --help            Muestra esta ayuda
```

#### Ejemplos de Casos de Uso:
```bash
# 1. Ejecución interactiva guiada (pregunta rol en terminal)
sudo omarchy-onboard

# 2. Configurar estación de desarrollo sin confirmaciones manuales
sudo omarchy-onboard --padre

# 3. Configurar máquina cliente aprovisionando perfiles múltiples
sudo omarchy-onboard --hija --users "omarchy niri nyxuri"

# 4. Simular acciones en modo seco
sudo omarchy-onboard --padre --dry-run
```
