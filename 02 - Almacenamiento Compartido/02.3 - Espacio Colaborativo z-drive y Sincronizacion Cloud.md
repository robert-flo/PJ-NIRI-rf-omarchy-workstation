## 🎯 Propósito y Visión Arquitectónica

El espacio colaborativo `/z-drive` resuelve de raíz el problema de duplicación de almacenamiento y fragmentación entre múltiples usuarios locales en Linux:

1. **Almacenamiento Centralizado Único (Cero Duplicados):**
   - Evita descargar múltiples veces bibliotecas pesadas (como los ~30.7 GB de `Idalia`), repositorios de código o archivos de subidas.
   - Todo el contenido en la nube se sincroniza hacia un único punto de montaje en disco: `/z-drive/`.
2. **Acceso Multi-Usuario Transparente:**
   - Todos los usuarios gestionados (`omarchy`, `niri`, `nyxuri`, etc.) y nuevos perfiles (`/etc/skel/`) acceden a sus carpetas mediante enlaces simbólicos simétricos en `$HOME`:
     - `~/Work/tries` ➔ `/z-drive/tries`
     - `~/Idalia` ➔ `/z-drive/idalia`
     - `~/Uploads-Gracie` ➔ `/z-drive/uploads-gracie`
     - `~/_boveda` ➔ `/z-drive/boveda`
     - `~/Cloud` ➔ `/z-drive/cloud` (Montaje FUSE Google Drive)
3. **Credenciales Compartidas sin Fricción:**
   - Archivo central `/etc/rclone/rclone.conf` con permisos `0660 root:wheel` y variable de entorno global `RCLONE_CONFIG=/etc/rclone/rclone.conf`.
   - Cualquier usuario perteneciente al grupo `wheel` puede disparar sincronizaciones manuales o refrescar tokens OAuth automáticamente.

## 🛡️ Seguridad Colaborativa: Permisos y Watcher en Tiempo Real

El directorio `/z-drive` está protegido mediante la utilidad `pj-domina-rf-shared_dir`:

- **Permisos Base:** `2770 root:wheel` (SetGID activo, sin lectura para otros).
- **ACLs POSIX Heredadas:** Garantizan que cualquier archivo o subdirectorio nuevo creado por cualquier usuario herede lectura, escritura y ejecución completa para `wheel`.
- **Demonio Watcher en Tiempo Real:** Servicio del sistema `z-drive-perms.service` respaldado por `inotifywait` (`/usr/local/bin/z-drive-perms_watcher.sh`) que normaliza cualquier permiso restrictivo introducido por compilaciones o herramientas externas al instante.

### 🛡️ Escudo Anti-Borrado de Carpetas Vacías (Protección Esencial)

Para evitar desastres en máquinas recién formateadas o clonadas:
- Si una carpeta local (`/z-drive/idalia` o `/z-drive/uploads-gracie`) está vacía (0 archivos), el script en modo **MAESTRO** aborta inmediatamente. Jamás sincronizará una carpeta vacía local hacia la nube porque rclone interpretaría que el usuario borró toda su biblioteca y eliminaría los archivos remotos.
- El instalador del playbook (`scripts/sync-stack/instalar.sh`) detecta esta condición y descarga primero la réplica completa (`--replica`) antes de activar los servicios de subida periódicos.
- Validación de Token OAuth: el instalador comprueba `rclone lsd gdrive:` y, en caso de token expirado o revocado, guía la reconexión autónoma interactiva (`rclone config reconnect gdrive:`).

### 🔗 Tratamiento Seguro de Enlaces Simbólicos (`--skip-links`)

Google Drive opera como almacenamiento de objetos sin soporte nativo para symlinks POSIX. Para prevenir bucles de recursión infinita en la nube y evitar advertencias innecesarias en los logs del sistema, tanto `sync-tries` como `synchub` ejecutan `rclone` con el parámetro **`--skip-links`**. Los enlaces simbólicos locales son preservados fielmente por `rsync` en el almacenamiento físico Btrfs (`ALMACEN_BTRFS`) y por Git en sus respectivos repositorios remotos.

## ⚡ Suite de Herramientas y Scripts Ejecutables

Todos los scripts están instalados globalmente en `/usr/local/bin/` con copias en `assets/system/usr/local/bin/`:

| Comando | Función y Alcance |
|---|---|
| `sync-tries` | Sincronización continua de `/z-drive/tries` hacia Drive y snapshots Btrfs CoW. Opera sin bloqueos artificiales de borrado masivo (apropiado para entorno de desarrollo con Git remoto), preservando el escudo de carpeta vacía. |
| `sync-idalia` | Sincronización de biblioteca multimedia (~30.7 GB). Admite rol `master` (subida a Drive) o `replica` (descarga protegida). |
| `sync-uploads-gracie` | Sincronización de transferencias y archivos de subida hacia Google Drive con topología master/replica. |
| `sync-all` | Orquestador que ejecuta la sincronización de todas las carpetas en lote. Soporta `--poweroff` / `--shutdown` para apagar la máquina de forma segura al terminar con éxito. |
| `sync-status` | Dashboard ejecutivo de terminal con métricas de archivos, tamaños, estados en vivo y servicios systemd. |
| `sync-hub-bar` | Generador de estado JSON para el módulo interactivo de Quickshell en la barra de Omarchy. |
| `sync-tries-watcher` | Demonio en segundo plano con debounce de 5 minutos de inactividad para sincronizar código automáticamente tras editarlo. |

## ⏰ Automatización del Sistema (Systemd Services & Timers)

Para evitar colisiones entre sesiones de distintos usuarios, los temporizadores corren de forma unificada a nivel de **sistema**:

```bash
# Ver el estado de todos los temporizadores de sincronización
systemctl list-timers | grep sync
```

- `sync-tries.timer`: Cada 30 minutos (y 5 min tras arranque del sistema).
- `sync-idalia.timer`: Cada 30 minutos (y 10 min tras arranque).
- `sync-uploads-gracie.timer`: Cada 30 minutos (y 15 min tras arranque).
- `sync-tries-watcher.service`: Demonio inotify continuo para detección de cambios en `/z-drive/tries`.
- `rclone-gdrive-mount.service`: Servicio de montaje FUSE continuo para Google Drive en `/z-drive/cloud` con caché VFS de 15 GB (`--allow-other`).

## 🛠️ Procedimiento de Mantenimiento: Agregar y Eliminar Carpetas de Sincronización

Para que cualquier agente de IA o el administrador gestione el ciclo de vida de las carpetas sincronizadas bajo la política Zero-Guesswork:

### Caso A: Eliminar una Carpeta de Sincronización (Ejemplo: `uploads-gracie`)

Si en el futuro se decide retirar una carpeta de la sincronización activa (por ejemplo `uploads-gracie`):

1. **Detener y deshabilitar los servicios y timers de systemd:**
   ```bash
   sudo systemctl disable --now sync-uploads-gracie.timer sync-uploads-gracie.service
   ```
2. **Eliminar los archivos de servicio del sistema y recargar el demonio:**
   ```bash
   sudo rm -f /etc/systemd/system/sync-uploads-gracie.service /etc/systemd/system/sync-uploads-gracie.timer
   sudo systemctl daemon-reload
   sudo systemctl reset-failed
   ```
3. **Eliminar el ejecutable y su configuración de rclone:**
   ```bash
   sudo rm -f /usr/local/bin/sync-uploads-gracie /etc/rclone/sync-uploads-gracie.conf
   ```
4. **Remover los enlaces simbólicos de los usuarios y plantillas:**
   ```bash
   for u in /home/* /etc/skel; do
       rm -f "$u/Uploads-Gracie"
   done
   ```
5. **Actualizar los orquestadores globales:**
   - Retirar la llamada en `/usr/local/bin/sync-all` y `scripts/sync-stack/sync-all`.
   - Retirar la fila de reporte en `/usr/local/bin/sync-status` y `scripts/sync-stack/sync-status`.
6. **Decisión sobre los datos locales en disco:**
   - Si se desean conservar localmente como almacenamiento compartido sin sincronización: mantener `/z-drive/uploads-gracie`.
   - Si se desean purgar localmente: `sudo rm -rf /z-drive/uploads-gracie`.
7. **Sincronizar el repositorio y espejo:**
   - Eliminar los archivos en `assets/system/` (`sync-uploads-gracie`, `sync-uploads-gracie.service`, `sync-uploads-gracie.timer`, `sync-uploads-gracie.conf`).
   - Actualizar esta nota y hacer commit en una rama auxiliar.

---

### Caso B: Agregar una Nueva Carpeta de Sincronización (Ejemplo: `documentos` hacia `gdrive:Documentos`)

Para añadir una nueva sincronización colaborativa y multiusuario:

1. **Crear la carpeta compartida en `/z-drive`:**
   ```bash
   sudo mkdir -p /z-drive/documentos
   sudo chown root:wheel /z-drive/documentos
   sudo chmod 2770 /z-drive/documentos
   sudo setfacl -d -m u::rwx,g::rwx,o::--- /z-drive/documentos
   ```
2. **Crear los enlaces simbólicos en los usuarios y `/etc/skel`:**
   ```bash
   for u in /home/* /etc/skel; do
       [[ -d "$u" ]] && ln -sfn /z-drive/documentos "$u/Documentos"
   done
   ```
3. **Crear el script de sincronización `/usr/local/bin/sync-documentos`:**
   - Tomar como base `sync-idalia` o `sync-uploads-gracie`.
   - **Obligatorio:** Mantener el **Escudo de Carpeta Vacía** (`if [[ $(find "$LOCAL_DIR" -type f | wc -l) -eq 0 ]]; then exit 2; fi`) para evitar borrado accidental en máquinas nuevas.
   - Guardar la plantilla en `scripts/sync-stack/sync-documentos` y copiar a `/usr/local/bin/` y `assets/system/usr/local/bin/`.
4. **Crear las unidades systemd:**
   - Crear `/etc/systemd/system/sync-documentos.service` y `sync-documentos.timer`.
   - Habilitar con `sudo systemctl daemon-reload && sudo systemctl enable --now sync-documentos.timer`.
5. **Integrar en el dashboard:**
   - Agregar una fila de verificación en `sync-status` y la llamada en `sync-all`.
6. **Sincronizar espejo (`assets/system/`) y documentar en este vault.**
