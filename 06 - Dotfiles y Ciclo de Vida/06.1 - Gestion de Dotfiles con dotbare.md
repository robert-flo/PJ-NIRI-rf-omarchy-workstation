# 📦 Gestión de Dotfiles con dotbare

> [!NOTE]
> **Navegación:**
> * Anterior: [[05.2 - Configuracion Craftzdog (nvim) y Distro Propia (rvim)|05.2 - Configuración Craftzdog (nvim) y Distro Propia (rvim)]]
> * Siguiente: [[06.2 - Validacion en Usuario Limpio (Testbench sura y nyxuri-test)|06.2 - Validación en Usuario Limpio (Testbench sura y nyxuri-test)]]
> * Volver a: [[00.0 - Mapa General del Sistema (MOC)|Índice General (MOC)]]

Este módulo describe el flujo de trabajo para versionar, auditar y mantener la configuración completa del escritorio Niri y Clavis utilizando **[dotbare](https://github.com/kazhala/dotbare)** (un gestor interactivo basado en repositorios Git *bare* sobre `$HOME` con soporte de `fzf`).

---

> [!IMPORTANT]
> **Modelo operativo en producción:**
> - Repositorio: [robert-flo/niri-dotfiles](https://github.com/robert-flo/niri-dotfiles), rama `master` = **verdad de producción**.
> - `niri` = **producción**; `sura` = **pruebas visuales**, desechable. Ambos usuarios llevan el repo con dotbare en `~/.cfg`.
> - Todo cambio de configuración de usuario: se prueba en `sura` $\rightarrow$ PR a `master` $\rightarrow$ `niri` hace `dotbare pull`. Si en `sura` falla, se descarta o se recrea desde el repositorio.
> - Lo que pueda vivir en los dotfiles vive en los dotfiles. Lo propio de cada máquina (`outputs.kdl`) queda fuera del repositorio.

---

## 0️⃣ Restaurar en una Máquina Nueva (`niri` y `sura`)

Requisitos: herramientas base instaladas, temas MacTahoe y `dotbare` presente en el sistema. Ejecutar desde el usuario administrador:

```bash
REPO_URL="https://github.com/robert-flo/niri-dotfiles.git"
cd /tmp
for TARGET_USER in niri sura; do
    TARGET_HOME="$(getent passwd "$TARGET_USER" | cut -d: -f6)"
    TARGET_UID="$(id -u "$TARGET_USER")"

    # 1. Clonar y hacer checkout
    sudo -u "$TARGET_USER" env HOME="$TARGET_HOME" DOTBARE_DIR="$TARGET_HOME/.cfg" DOTBARE_TREE="$TARGET_HOME" \
        bash -c "cd ~ && dotbare finit -y -u '$REPO_URL' </dev/null"

    # 2. Configurar refspecs de fetch y rama upstream
    G="sudo -u $TARGET_USER git --git-dir=$TARGET_HOME/.cfg --work-tree=$TARGET_HOME"
    $G config remote.origin.fetch '+refs/heads/*:refs/remotes/origin/*'
    $G config status.showUntrackedFiles no
    $G fetch origin && $G branch -u origin/master master

    # 3. Post-instalación (gsettings, servicios Clavis, Matugen, validación)
    sudo -u "$TARGET_USER" env HOME="$TARGET_HOME" XDG_RUNTIME_DIR="/run/user/$TARGET_UID" \
        bash -c '~/.local/bin/niri-dotfiles-postinstall'
done
```

> [!WARNING]
> **Antes de alinear un usuario que ya tiene configuración**, toma un snapshot de `/home` ([[01.5 - Snapshots y Recuperacion con Btrfs|01.5]]). `finit -u` reemplaza archivos versionados; los anteriores quedan respaldados en `~/.local/share/dotbare/`.

---

## 🎯 Por qué dotbare

1. **Sin enlaces simbólicos frágiles:** Los archivos residen directamente en `$HOME` y `~/.config/`, evitando estructuras intermedias que complican la edición.
2. **Repositorio Bare (`~/.cfg`):** El repositorio Git no contiene un directorio de trabajo normal visible, manteniendo el home limpio.
3. **Control granular:** Solo los archivos explícitamente agregados con `dotbare add` son seguidos por Git (`status.showUntrackedFiles=no`).

sudo -u "$TARGET_USER" env HOME="$TARGET_HOME" DOTBARE_DIR="$TARGET_HOME/.cfg" DOTBARE_TREE="$TARGET_HOME" \
  GIT_CONFIG_PARAMETERS="'init.defaultBranch=master'" bash -c 'cd ~
dotbare finit -y </dev/null

## 4️⃣ Auditoría Estricta de Secretos (Antes de Compartir)

```bash
sudo -u "$TARGET_USER" bash -c 'cd ~; git --git-dir=.cfg --work-tree=. ls-files -z | xargs -0 rg -n -i -I \
  -e "ghp_[A-Za-z0-9]{20,}" -e "github_pat_" -e "-----BEGIN .*PRIVATE KEY" \
  -e "(password|passwd|secret|api[_-]?key|token)\s*[=:]\s*\S{6,}" -e "@(gmail|outlook|hotmail)\."'
```

*Si la búsqueda arroja cero coincidencias no autorizadas, el árbol está limpio para ser compartido.*

## 5️⃣ Flujo de Trabajo Diario (`sura` → `niri`)

```bash
set -gx DOTBARE_DIR "$HOME/.cfg"
set -gx DOTBARE_TREE "$HOME"
```

**1. En `sura` (pruebas):**
```bash
dotbare checkout -b ajuste/esquinas        # rama auxiliar, nunca commit directo a master
# ... editar y probar visualmente en la sesión Niri de sura ...
dotbare fadd
dotbare commit -m "Ajustar curvatura de esquinas"
dotbare push -u origin ajuste/esquinas
gh pr create --repo robert-flo/niri-dotfiles --base master --head ajuste/esquinas
```

**2. Tras probar y antes de mergear:**
Rebasar sobre `master`, mergear el PR y borrar ramas local y remota:
```bash
dotbare checkout master && dotbare pull --ff-only
dotbare branch -d ajuste/esquinas
```

**3. En `niri` (producción):**
```bash
dotbare pull --ff-only
~/.local/bin/niri-dotfiles-postinstall     # solo si el cambio toca gsettings, servicios o colores
```

---

## 6️⃣ Script de Post-Instalación (`niri-dotfiles-postinstall`)

Versionado en el repositorio de dotfiles, realiza:
1. Adapta `/home/niri` $\rightarrow$ `$HOME` en `~/.config/clavis/config.json` y `~/.config/obsidian/obsidian.json`.
2. `gsettings`: tema GTK `MacTahoe-Dark`, iconos `MacTahoe-dark`, botones a la izquierda y cursor leído de Clavis.
3. Habilita `clavis-shell.service` y `clavis-clipboard.service`.
4. Genera los colores Matugen desde el wallpaper de Clavis.
5. Valida `config.kdl` con `niri validate`.
