# 🧪 Validación en Usuario Limpio (Testbench `sura` y `nyxuri-test`)

> [!NOTE]
> **Navegación de Capa:**
> * Anterior: [[06.1 - Gestion de Dotfiles con dotbare]]
> * Siguiente: [[06.3 - Dotfiles de Omarchy para gracie (Planificado)]]
> * Subir al Hub: [[06.0 - Dotfiles y Ciclo de Vida (MOC)|📑 Hub de Capa]]

Este módulo establece una metodología formal para verificar la portabilidad, estabilidad e idempotencia de la configuración en usuarios dedicados de pruebas (**testbench**). Permite certificar que los dotfiles funcionan correctamente en un entorno limpio sin comprometer las cuentas de producción diaria.

---

> [!IMPORTANT]
> **Modelo de Testbenches Permanentes en la Máquina:**
> 
> | Entorno | Usuario Producción | Usuario Testbench Desechable | Repositorio de Verdad |
> |---|---|---|---|
> | **Clavis Shell** | `niri` | `sura` / `niri-test` | [robert-flo/rf-dotfiles](https://github.com/robert-flo/rf-dotfiles) (vía Chezmoi) |
> | **Nyxuri Shell** | `nyxuri` | `nyxuri-test` | [robert-flo/PJ-NIRI-fo-nyxuri](https://github.com/robert-flo/PJ-NIRI-fo-nyxuri) + Chezmoi |
> | **Omarchy 4.6** | `<admin>` (`rollo`) | `omarchy-test` | [robert-flo/rf-dotfiles](https://github.com/robert-flo/rf-dotfiles) (vía Chezmoi) |
> 
> - `sura`/`niri-test` y `nyxuri-test` tienen los mismos grupos y privilegios administrativos que las cuentas de producción (`wheel,audio,input,video`, sudo sin contraseña con `verifypw = any`, linger).
> - Todo cambio se prueba visual y funcionalmente en el testbench correspondiente antes de mergear a la rama `master`.
> - **Desechables pero siempre presentes:** Si una prueba deja el testbench en un estado inconsistente, se limpia (`piloto-home.sh wipe --user <test-user>`) y se recrea de inmediato ejecutando `make converge` o `sudo -u <test-user> -H chezmoi apply --source=/z/rf-dotfiles --force`.

---

## 🎯 Objetivo de la Prueba

1. Clonar e inicializar el repositorio de dotfiles en una cuenta sin configuraciones previas.
2. Identificar y resolver problemas comunes de portabilidad:
   - Rutas absolutas hardcodeadas (`/home/<usuario_original>` vs `$HOME`).
   - Enlaces simbólicos rotos o no relativos.
   - Ajustes residentes fuera del control de versiones (GSettings, servicios systemd, carpetas vacías).
3. Validar mediante una lista de control interactiva (*QA Checklist*) tanto en consola como en sesión gráfica Wayland.
4. Desmantelar y recrear de forma limpia el entorno cuando sea necesario.

---

## 1️⃣ Creación del Usuario de Pruebas (Testbench)

```bash
TEST_USER="${1:-sura}"

# 1. Crear usuario con grupos de hardware y wheel
sudo useradd -m -s /bin/bash -G wheel,audio,input,video,kvm,storage "$TEST_USER"

# 2. Asignar contraseña idéntica a la de producción
echo "Asigna la contraseña para el usuario de pruebas:"
sudo passwd "$TEST_USER"

# 3. Permisos de sudo permanente
tmp=$(mktemp)
printf "%s ALL=(ALL) NOPASSWD: ALL\nDefaults:%s verifypw = any\n" "$TEST_USER" "$TEST_USER" > "$tmp"
sudo visudo -cf "$tmp" && sudo install -m 0440 -o root -g root "$tmp" "/etc/sudoers.d/04_${TEST_USER}"
rm -f "$tmp"

# 4. Habilitar systemd linger
sudo loginctl enable-linger "$TEST_USER"
```

## 2️⃣ Despliegue de Dotfiles

### Para Clavis (`sura`):
```bash
REPO_URL="https://github.com/robert-flo/niri-dotfiles.git"
TEST_HOME="$(getent passwd "sura" | cut -d: -f6)"
TEST_UID="$(id -u "sura")"

sudo -u sura env HOME="$TEST_HOME" DOTBARE_DIR="$TEST_HOME/.cfg" DOTBARE_TREE="$TEST_HOME" bash -c "
cd ~
dotbare finit -y -u '$REPO_URL' </dev/null
"

# Ejecutar script de post-instalación
sudo -u sura env HOME="$TEST_HOME" XDG_RUNTIME_DIR="/run/user/$TEST_UID" bash -c "
~/.local/bin/niri-dotfiles-postinstall
"
```

### Para Nyxuri (`nyxuri-test`):
```bash
sudo -u nyxuri-test -H nyxuri on niri noctalia kitty fastfetch fish starship theme wallpapers xdg-desktop-portal zed
sudo -u nyxuri-test -H nyxuri shell set nyxuri-shell /usr/local/bin/nyxuri-shell
```

## 3️⃣ Diagnóstico Automatizado de Consola

```bash
# 1. Comprobar sintaxis de Niri en el testbench
sudo -u sura niri validate -c /home/sura/.config/niri/config.kdl
sudo -u nyxuri-test niri validate -c /home/nyxuri-test/.config/niri/config.kdl

# 2. Auditar que no existan rutas residuales de otro usuario
sudo -u sura bash -c "
cd ~
git --git-dir=.cfg ls-files -z | xargs -0 grep -Hn '/home/' | grep -v 'sura' || echo '✅ Árbol 100% portable'
"
```

## 4️⃣ Lista de Verificación Visual (QA Checklist en Sesión Gráfica)

Iniciar sesión en **SDDM** seleccionando el usuario `sura` (Niri) o `nyxuri-test`:

> [!CHECKLIST]
> - [ ] **Shell de Escritorio:** Los paneles, reloj, dock y widgets aparecen con fluidez y sin errores en journalctl.
> - [ ] **Wallpaper:** Se renderiza el fondo estático o video animado asignado.
> - [ ] **Focus Ring:** Las ventanas activas muestran el contorno dinámico reactivo al fondo de pantalla.
> - [ ] **Animaciones:** Las transiciones de espacios de trabajo y apertura de ventanas tienen curvas spring elásticas.
> - [ ] **Cursor:** Se muestra el cursor `MacTahoe-dark-cursors` en aplicaciones Wayland y XWayland.
> - [ ] **Botones Semáforo:** Las apps GTK muestran botones rojo/amarillo/verde alineados a la izquierda.
> - [ ] **Terminal:** Abre directamente con la tipografía y colores correctos.
> - [ ] **Aplicaciones Integradas:** mpv, Obsidian, Thunderbird y SPlayer-Next operan con sus respectivos temas.

## 5️⃣ Desmantelamiento y Recreación Limpia del Testbench

Si una prueba deja el entorno inestable, desmantelar y recrear:

```bash
TEST_USER="niri-test"  # O nyxuri-test / sura

# 1. Detener procesos y linger
sudo loginctl disable-linger "$TEST_USER"
sudo pkill -u "$TEST_USER" || true

# 2. Eliminar usuario y directorio personal
sudo userdel -r "$TEST_USER"
sudo rm -f "/etc/sudoers.d/04_${TEST_USER}"

echo "✅ Testbench eliminado. Listo para ser recreado desde el paso 1."
```

## 6️⃣ Protocolo de Wipe y Restauración Prístina de Modificaciones en Usuarios

> [!IMPORTANT]
> **REGLA ESTRICTA PARA AGENTES DE IA (Zero-Assumptions Policy):**
> Cuando el usuario solicite un **"wipe"**, **"reseteo"** o **"volver a estado original"** las modificaciones o pruebas en las cuentas:
> 1. **El agente NUNCA debe ejecutar la limpieza a ciegas sin preguntar.**
> 2. **El agente DEBE preguntar explícitamente en cuáles usuarios se desea aplicar la restauración.** 
>    - La recomendación habitual sugerirá los usuarios de prueba (`niri-test` y/o `nyxuri-test`).
>    - Sin embargo, debe permitir al usuario confirmar si también abarca cuentas de producción (`niri`, `nyxuri`), cuentas estables (`nyxuri-legacy`) o administrativas (`omarchy`).
> 3. Una vez confirmados los usuarios destino, ejecutar de forma idempotente el procedimiento según la familia de configuración correspondiente:

### 🅰️ Procedimiento para Familia Dotbare (Clavis / Niri: `niri`, `niri-test`, `sura`)

Restaura el árbol completo de dotfiles desde la rama `master` del repositorio oficial de dotbare sin dejar archivos huérfanos o configs rotas:

```bash
TARGET_USER="niri-test" # O niri
TARGET_HOME="$(getent passwd "$TARGET_USER" | cut -d: -f6)"
TARGET_UID="$(id -u "$TARGET_USER")"
REPO_URL="https://github.com/robert-flo/niri-dotfiles.git"

cd /tmp

# 1. Re-inicializar dotbare en modo forzado limpio
sudo -u "$TARGET_USER" env HOME="$TARGET_HOME" DOTBARE_DIR="$TARGET_HOME/.cfg" DOTBARE_TREE="$TARGET_HOME" \
    bash -c "cd ~ && rm -rf ~/.cfg ~/.local/share/dotbare && dotbare finit -y -u '$REPO_URL' </dev/null"

# 2. Configurar refspecs de fetch y rama upstream
G="sudo -u $TARGET_USER git --git-dir=$TARGET_HOME/.cfg --work-tree=$TARGET_HOME"
$G config remote.origin.fetch '+refs/heads/*:refs/remotes/origin/*'
$G config status.showUntrackedFiles no
$G fetch origin && $G branch -u origin/master master

# 3. Ejecutar postinstall de dotfiles (gsettings, servicios Clavis, Matugen, etc.)
sudo -u "$TARGET_USER" env HOME="$TARGET_HOME" XDG_RUNTIME_DIR="/run/user/$TARGET_UID" \
    bash -c '~/.local/bin/niri-dotfiles-postinstall'

# 4. Verificación de salud Neovim (Nativo XDG sin symlinks)
sudo -u "$TARGET_USER" rvim --headless -c "echo '[OK] rvim verified!'" -c "qa"
sudo -u "$TARGET_USER" 2kvim --headless -c "echo '[OK] 2kvim verified!'" -c "qa"

# 5. Verificación de salud Niri
sudo -u "$TARGET_USER" niri validate -c "$TARGET_HOME/.config/niri/config.kdl"
```

### 🅱️ Procedimiento para Familia Nyxuri Edge (`nyxuri`, `nyxuri-test`)

Restaura las unidades de configuración modular y shell experimental sincronizadas con `/opt/src/nyxuri` (rama `personal`):

```bash
TARGET_USER="nyxuri-test" # O nyxuri
TARGET_HOME="$(getent passwd "$TARGET_USER" | cut -d: -f6)"
BASE_UNITS="niri noctalia kitty fastfetch fish starship theme wallpapers xdg-desktop-portal zed"
SHELL_UNITS="shell.bar shell.desktopcards shell.dock shell.keystone shell.launcher shell.lock shell.notifications shell.regionselector shell.session shell.settings shell.sidebars shell.wallpaper"

# 1. Asegurar sincronización del repositorio base en /opt/src/nyxuri
git -C /opt/src/nyxuri fetch origin && git -C /opt/src/nyxuri reset --hard origin/personal

# 2. Desplegar unidades y fijar shell
for unit in $BASE_UNITS $SHELL_UNITS; do
    sudo -u "$TARGET_USER" -H nyxuri on "$unit"
done
sudo -u "$TARGET_USER" -H nyxuri shell set nyxuri-shell /usr/local/bin/nyxuri-shell
sudo -u "$TARGET_USER" -H python3 -c "import sys; sys.path.insert(0, '/opt/src/nyxuri'); from nyxuri.deploy.templates import _phase_render_templates; _phase_render_templates()"

# 3. Verificación de salud Neovim (Nativo XDG sin symlinks)
sudo -u "$TARGET_USER" rvim --headless -c "echo '[OK] rvim verified!'" -c "qa"
sudo -u "$TARGET_USER" 2kvim --headless -c "echo '[OK] 2kvim verified!'" -c "qa"

# 4. Verificación de salud Niri
sudo -u "$TARGET_USER" niri validate -c "$TARGET_HOME/.config/niri/config.kdl"
```

### 🅳️ Re-aprovisionamiento y Validación del Ecosistema Google y Android Studio (Común a Todos)

Tras restaurar cualquier usuario (`omarchy`, `niri`, `nyxuri`, etc.), garantizar que su entorno herede el acceso a las herramientas globales y puntos de desarrollo móvil:

```bash
TARGET_USER="<usuario>"
TARGET_HOME="$(getent passwd "$TARGET_USER" | cut -d: -f6)"

# 1. Variables de entorno en Bash
if ! grep -q "ANDROID_HOME" "$TARGET_HOME/.bashrc" 2>/dev/null; then
    cat << "EOF" >> "$TARGET_HOME/.bashrc"

# --- ANDROID & JAVA ENVIRONMENT ---
export ANDROID_HOME="/opt/android-sdk"
export ANDROID_USER_HOME="$HOME/.android"
export ANDROID_PROJECTS_DIR="/z/android-projects"
export PATH="$PATH:$ANDROID_HOME/emulator:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$HOME/.local/bin"
# --- FIN ANDROID & JAVA ENVIRONMENT ---
EOF
    chown "$TARGET_USER:$TARGET_USER" "$TARGET_HOME/.bashrc"
fi

# 2. Variables de entorno en Fish Shell
mkdir -p "$TARGET_HOME/.config/fish/conf.d"
cat << "EOF" > "$TARGET_HOME/.config/fish/conf.d/android.fish"
# --- ANDROID & JAVA ENVIRONMENT (FISH) ---
set -gx ANDROID_HOME "/opt/android-sdk"
set -gx ANDROID_USER_HOME "$HOME/.android"
set -gx ANDROID_PROJECTS_DIR "/z/android-projects"

fish_add_path -a $ANDROID_HOME/emulator $ANDROID_HOME/platform-tools $ANDROID_HOME/cmdline-tools/latest/bin $HOME/.local/bin
# --- FIN ANDROID & JAVA ENVIRONMENT ---
EOF
chown -R "$TARGET_USER:$TARGET_USER" "$TARGET_HOME/.config/fish"

# 3. Comprobar acceso de escritura en almacenamiento colaborativo
sudo -u "$TARGET_USER" test -w /opt/android-sdk && echo "✅ /opt/android-sdk [OK]" || echo "❌ /opt/android-sdk [FAIL]"
sudo -u "$TARGET_USER" test -w /z/android-projects && echo "✅ /z/android-projects [OK]" || echo "❌ /z/android-projects [FAIL]"

# 4. Comprobar binarios globales del stack
sudo -u "$TARGET_USER" which agy firebase google-chrome android-studio-canary antigravity antigravity-ide adb
```

### 🅲️ Procedimiento para Familia Nyxuri Stable (`nyxuri-legacy`)

Restaura la configuración oficial estable de upstream basada en el release tag `v3.1.0` en `/opt/src/nyxuri-stable`:

```bash
TARGET_USER="nyxuri-legacy"
TARGET_HOME="$(getent passwd "$TARGET_USER" | cut -d: -f6)"

# 1. Ejecutar instalación de configs estables no-interactiva
sudo -u "$TARGET_USER" env HOME="$TARGET_HOME" python3 -c '
import sys
sys.path.insert(0, "/opt/src/nyxuri-stable")
sys.argv = ["nyxuri", "install", "config"]
from nyxuri.cli import main
main()
' </dev/null

# 2. Asegurar enlace simbólíco de efectos Niri requeridos por el compositor
sudo -u "$TARGET_USER" ln -sfn "$TARGET_HOME/.config/niri/effects_normal.kdl" "$TARGET_HOME/.config/niri/effects.kdl"

# 3. Verificación de salud Neovim (Nativo XDG sin symlinks)
sudo -u "$TARGET_USER" rvim --headless -c "echo '[OK] rvim verified!'" -c "qa"
sudo -u "$TARGET_USER" 2kvim --headless -c "echo '[OK] 2kvim verified!'" -c "qa"

# 4. Verificación de salud Niri
sudo -u "$TARGET_USER" niri validate -c "$TARGET_HOME/.config/niri/config.kdl"
```
