# 🧪 Validación en Usuario Limpio (Testbench `sura` y `nyxuri-test`)

> [!NOTE]
> **Navegación:**
> * Anterior: [[06.1 - Gestion de Dotfiles con dotbare|06.1 - Gestión de Dotfiles con dotbare]]
> * Siguiente: [[06.3 - Dotfiles de Omarchy para gracie (Planificado)|06.3 - Dotfiles de Omarchy para gracie (Planificado)]]
> * Volver a: [[06.0 - Dotfiles y Ciclo de Vida (MOC)|📑 Índice de Capa]]

Este módulo establece una metodología formal para verificar la portabilidad, estabilidad e idempotencia de la configuración en usuarios dedicados de pruebas (**testbench**). Permite certificar que los dotfiles funcionan correctamente en un entorno limpio sin comprometer las cuentas de producción diaria.

---

> [!IMPORTANT]
> **Modelo de Testbenches Permanentes en la Máquina:**
> 
> | Entorno | Usuario Producción | Usuario Testbench Desechable | Repositorio de Verdad |
> |---|---|---|---|
> | **Clavis Shell** | `niri` | `sura` | [robert-flo/niri-dotfiles](https://github.com/robert-flo/niri-dotfiles) |
> | **Nyxuri Shell** | `nyxuri` | `nyxuri-test` | [robert-flo/PJ-NIRI-fo-nyxuri](https://github.com/robert-flo/PJ-NIRI-fo-nyxuri) |
> 
> - `sura` y `nyxuri-test` tienen los mismos grupos y privilegios administrativos que las cuentas de producción (`wheel,audio,input,video`, sudo sin contraseña con `verifypw = any`, linger).
> - Todo cambio se prueba visual y funcionalmente en el testbench correspondiente antes de mergear a la rama `master` / `personal`.
> - **Desechables pero siempre presentes:** Si una prueba deja el testbench en un estado inconsistente, se borra y se recrea de inmediato desde el repositorio base.

---

## 🎯 Objetivo de la Prueba

1. Clonar e inicializar el repositorio de dotfiles en una cuenta sin configuraciones previas.
2. Identificar y resolver problemas comunes de portabilidad:
   - Rutas absolutas hardcodeadas (`/home/<usuario_original>` vs `$HOME`).
   - Enlaces simbólicos rotos o no relativos.
   - Ajustes residentes fuera del control de versiones (GSettings, servicios systemd, carpetas vacías).
3. Validar mediante una lista de control interactiva (*QA Checklist*) tanto en consola como en sesión gráfica Wayland.
4. Desmantelar y recrear de forma limpia el entorno cuando sea necesario.

---

## 1️⃣ Creación del Usuario de Pruebas (Testbench)

```bash
TEST_USER="${1:-sura}"

# 1. Crear usuario con grupos de hardware y wheel
sudo useradd -m -s /bin/bash -G wheel,audio,input,video,kvm,storage "$TEST_USER"

# 2. Asignar contraseña idéntica a la de producción
echo "Asigna la contraseña para el usuario de pruebas:"
sudo passwd "$TEST_USER"

# 3. Permisos de sudo permanente
tmp=$(mktemp)
printf "%s ALL=(ALL) NOPASSWD: ALL\nDefaults:%s verifypw = any\n" "$TEST_USER" "$TEST_USER" > "$tmp"
sudo visudo -cf "$tmp" && sudo install -m 0440 -o root -g root "$tmp" "/etc/sudoers.d/04_${TEST_USER}"
rm -f "$tmp"

# 4. Habilitar systemd linger
sudo loginctl enable-linger "$TEST_USER"
```

## 2️⃣ Despliegue de Dotfiles

### Para Clavis (`sura`):
```bash
REPO_URL="https://github.com/robert-flo/niri-dotfiles.git"
TEST_HOME="$(getent passwd "sura" | cut -d: -f6)"
TEST_UID="$(id -u "sura")"

sudo -u sura env HOME="$TEST_HOME" DOTBARE_DIR="$TEST_HOME/.cfg" DOTBARE_TREE="$TEST_HOME" bash -c "
cd ~
dotbare finit -y -u '$REPO_URL' </dev/null
"

# Ejecutar script de post-instalación
sudo -u sura env HOME="$TEST_HOME" XDG_RUNTIME_DIR="/run/user/$TEST_UID" bash -c "
~/.local/bin/niri-dotfiles-postinstall
"
```

### Para Nyxuri (`nyxuri-test`):
```bash
sudo -u nyxuri-test -H nyxuri on niri noctalia kitty fastfetch fish starship theme wallpapers xdg-desktop-portal zed
sudo -u nyxuri-test -H nyxuri shell set nyxuri-shell /usr/local/bin/nyxuri-shell
```

## 3️⃣ Diagnóstico Automatizado de Consola

```bash
# 1. Comprobar sintaxis de Niri en el testbench
sudo -u sura niri validate -c /home/sura/.config/niri/config.kdl
sudo -u nyxuri-test niri validate -c /home/nyxuri-test/.config/niri/config.kdl

# 2. Auditar que no existan rutas residuales de otro usuario
sudo -u sura bash -c "
cd ~
git --git-dir=.cfg ls-files -z | xargs -0 grep -Hn '/home/' | grep -v 'sura' || echo '✅ Árbol 100% portable'
"
```

## 4️⃣ Lista de Verificación Visual (QA Checklist en Sesión Gráfica)

Iniciar sesión en **SDDM** seleccionando el usuario `sura` (Niri) o `nyxuri-test`:

> [!CHECKLIST]
> - [ ] **Shell de Escritorio:** Los paneles, reloj, dock y widgets aparecen con fluidez y sin errores en journalctl.
> - [ ] **Wallpaper:** Se renderiza el fondo estático o video animado asignado.
> - [ ] **Focus Ring:** Las ventanas activas muestran el contorno dinámico reactivo al fondo de pantalla.
> - [ ] **Animaciones:** Las transiciones de espacios de trabajo y apertura de ventanas tienen curvas spring elásticas.
> - [ ] **Cursor:** Se muestra el cursor `MacTahoe-dark-cursors` en aplicaciones Wayland y XWayland.
> - [ ] **Botones Semáforo:** Las apps GTK muestran botones rojo/amarillo/verde alineados a la izquierda.
> - [ ] **Terminal:** Abre directamente con la tipografía y colores correctos.
> - [ ] **Aplicaciones Integradas:** mpv, Obsidian, Thunderbird y SPlayer-Next operan con sus respectivos temas.

---

## 5️⃣ Desmantelamiento y Recreación Limpia del Testbench

Si una prueba deja el entorno inestable, desmantelar y recrear:

```bash
TEST_USER="sura"  # O nyxuri-test

# 1. Detener procesos y linger
sudo loginctl disable-linger "$TEST_USER"
sudo pkill -u "$TEST_USER" || true

# 2. Eliminar usuario y directorio personal
sudo userdel -r "$TEST_USER"
sudo rm -f "/etc/sudoers.d/04_${TEST_USER}"

echo "✅ Testbench eliminado. Listo para ser recreado desde el paso 1."
```
